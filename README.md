## 特長
- **手元で完結**：インターネットもアカウントも要りません。帳簿は1つのファイル（.dmbl）で、証憑もまとめて持ち運べます
- **電子帳簿保存法（優良な電子帳簿）に対応**：訂正・削除の履歴、改ざんの確認、届出の案内まで
- **日々の記帳から決算書まで**：出納帳の形の入力、家事按分、固定資産台帳と減価償却、青色申告決算書（4ページ）
- **守りもしっかり**：自動バックアップ、帳簿ファイルの暗号化（任意）、ユーザーごとの権限、月・年度の締め

## 技術スタック
- Runtime: Bun / Framework: Tauri 2 / Frontend: React + TypeScript
- Icons: Lucide React / Database: SQLite（Rust 側の rusqlite。接続は帳簿ファイルごとに1本で、トランザクションを使う。暗号化のため SQLCipher 入りでビルドする）

## 使い方
```
bun install
bun tauri dev     # 開発モードで起動
bun test          # 会計ロジックのテスト
```

## 締め（月・年度）
- 年度ごとに**「何月まで締めたか」**を持ちます（`fiscal_closings.period_end` = 締めた月の末日）
  - **月の締め**：締めた月までの仕訳（登録・訂正・削除）は変更できません。通帳と照らし合わせた月、確認が済んだ月などを締めておくと、うっかり変えてしまうのを防げます
  - **年の締め**（12月まで締める）：期首残高・家事按分・減価償却・その年度の科目名なども変更できません。厳密モードでは確認コードを出します
- 事業者設定の「締め（月・年度）」で、年度ごとに「○月まで」を選んで締めます。直すときは「締めを戻す」で、**どの月までの締めに戻すかを1回選ぶだけ**です（年の締めから「10月まで」に戻せば、11・12月だけ直せる）。締めと戻しは管理者だけ。厳密モードでは戻す理由が必須で、締めと戻しは履歴に「9月まで締め → 締めなしに戻す（理由：…）」のように残ります（毎回「編集しますか？」と聞く方式は、反射的に「はい」を押されやすいため採っていません）
- 翌年への繰越は「翌年を始める」だけで、前の年は締めません（**「この年を締める」**にチェックしたときだけ年の締めをする。最初はチェックなし）。前の年の決算を直しながら翌年の入力を始められます。直したら繰越をやり直します（ずれは画面上部で知らせる）
- 前の年度を直して、翌年の期首残高が繰越額とずれたときは、画面上部でお知らせし、繰越のやり直しを促します
- 締めは画面だけでなく、DB のトリガーでも確認しています（締めた月への仕訳の書き込み、年の締めをした年度の期首残高などへの書き込みを拒否）
- この仕組みを入れる前に作った帳簿は、開いたときに一度だけ、繰越済みの年度を年の締めにします

## 決算整理仕訳
- 仕訳に「決算整理」の印を持てます（振替伝票・仕訳の訂正画面の「決算整理仕訳」、帳簿入力で「決算整理」を選んで入力）。日付は年度末（12月31日）だけです
- 帳簿入力では、12月のあとの「決算整理」に出ます（12月を選んでも決算整理仕訳は出ない）。残高の推移でも、年度末のほかの仕訳よりあとに並びます
- 家事按分の年末の振替（年度末の日付）も決算整理仕訳になります
- 仕訳日記帳・CSV（「決算整理」の列）にも印が出ます。CSV 取り込みでも「決算整理」の列に何か入っていれば決算整理仕訳です
- 厳密モードでは、履歴の写しと記録の連鎖にも印が入ります（印の無い仕訳の記録は今までと同じハッシュ）

## 固定資産台帳・減価償却
- 10万円以上の備品・車・建物などを登録すると、年度ごとの減価償却費を計算します（計算は `lib/depreciation.ts`）
  - **定額法**（平成19年4月1日以後に取得したもの）：取得価額 × 償却率 × 使った月数 / 12（1円未満は切り上げ）。償却率は 1/耐用年数 を小数第3位で切り上げたもの。最後は 1円（備忘価額）を残す
  - **一括償却資産**（10万円以上20万円未満）：1/3 ずつ3年。月割りしない。売却・除却しても3年続ける
  - **少額減価償却資産**（青色申告・30万円未満）：使い始めた年に全額。1年の合計が300万円を超えると知らせる
- **事業専用割合**は資産ごとに持ちます。償却費のうち事業分（1円未満切り捨て）を減価償却費、残りを事業主貸にします（未償却残高は償却費の全額だけ減る）
- 年末に「減価償却費（事業分）＋事業主貸（家事分） / 資産の科目」の決算整理仕訳（12月31日付）を1本作ります。台帳を直したら「作り直す」で同じ仕訳を訂正します（作成済みの仕訳と計算が違えば知らせる）
- 資産を買った仕訳は振替伝票で入れます。資産の科目ごとに、帳簿の期末残高と台帳の未償却残高を並べて照合できます
- domble を使う前から持っている資産は、「その年の期首の未償却残高」から計算を始められます
- 売却・除却した日を入れると、その月まで償却します（帳簿から外す仕訳は振替伝票で入れる）
- 台帳の追加・変更・削除は履歴に残ります（厳密モード）。減価償却費は家事按分の画面ではなく、ここで資産ごとに割合を決めます（台帳から作った仕訳は、家事按分の年末の振替の計算に入れない）
- 科目に「構築物」「一括償却資産」「ソフトウェア」を足しました（既存の帳簿にも開いたときに入る）

## 決算書（2〜3ページ）
- 金額は帳簿から出します（集計は `lib/statements.ts`）
  - **月別売上（収入）金額及び仕入金額**：家事消費等・雑収入を除く収益の科目を月ごとに、仕入高を月ごとに集計。家事消費等・雑収入は年間で
  - **給料賃金・専従者給与・利子割引料・地代家賃・税理士等の報酬の内訳**：支払先ごと。支払先は、仕訳の取引先 → 明細の補助科目 → どちらも無ければ「支払先の指定なし」の順で決める（人ごとに補助科目を作っておくと分かれる）
  - 家事按分している科目は、本年中の支払額（家事分を含む）と必要経費算入額（事業分）を分けて出す
  - **減価償却費の計算**：固定資産台帳から（少額減価償却資産は摘要に「措法28の2」）
  - 税理士・弁護士等の報酬は、支払手数料の支払先から「書く」にチェックしたものだけ。利子割引料は金融機関の分のチェックを外す（印刷に出ない）
- 帳簿から出せない項目（年齢・従事月数・賞与・源泉徴収税額・続柄・支払先の住所・賃借物件・権利金等・借入金の残高・資産の数量・特殊事情）は、決算書の画面でそのまま書き込みます。年度ごとに保存し（`statement_notes`）、締めた年度は変えられません。帳簿そのものではないので履歴には残しません

## 仕訳の CSV 取り込み
- 仕訳日記帳の「CSV 取り込み」から。形式は **仕訳日記帳の CSV 書き出しと同じ**（書き出したものをそのまま取り込める）。文字コードは UTF-8 / Shift_JIS
- 列は見出しの名前で探します（順番は問わない）。必須は 日付・借方科目・借方金額・貸方科目・貸方金額。任意で 伝票No・借方補助・貸方補助・摘要・取引先・状態
- 同じ伝票No の行は1つの仕訳（複合仕訳）になります。伝票No が無ければ1行で1つ。状態が「削除済み」の行は飛ばします
- 日付は年つき（2026-01-05、2026/1/5、2026年1月5日、20260105）
- 科目・補助科目・取引先は名前で探します（全角半角・空白の違いは無視）。一覧に無い名前は自動で作らず、問題として知らせます
- 取り込む前に中身を確かめて一覧で見せます。1か所でも問題があれば、行番号つきで知らせて1件も取り込みません。取り込みは1つのトランザクションなので、途中で失敗しても1件も残りません
- 厳密モードでは、登録の履歴に「CSV 取り込み（ファイル名）」と残ります。登録日時は取り込んだ日時なので、過去の仕訳は「遅れて登録」と表示されます

## 入力期間
- 優良な電子帳簿の「通常の期間を経過した後に入力した場合は、その事実を確認できること」に対応するもの
- 取引日から、事業者設定の **入力期間（日）** を過ぎて登録した仕訳を、仕訳日記帳で「遅れて登録」と表示します。
  「入力期間を過ぎて登録したもの」で絞り込め、CSV には登録日時・登録までの日数・入力期間を過ぎたかが出ます
- 既定は 70 日（業務処理サイクル方式の「最長2か月 + おおむね7営業日」の目安）。事務処理規程などで決めた期間に合わせます
- 登録日時は、厳密モードでは登録時の履歴（`entry_history` の create。記録の連鎖に入っている）から取ります。仕訳の `created_at` を直接書き換えても結果は変わりません
- 入力期間の変更は、厳密モードでは履歴に残ります（どの仕訳が「遅れて登録」に当たるかが変わるため）
- 訂正は対象外です（訂正の事実は訂正・削除履歴で確認できるため）。判定は「最初に登録した日」で行います

## 証憑（電子取引データ）
- メールなどで受け取った請求書・領収書を、**受け取ったファイルのまま**（変換せずに）帳簿ファイルの中に保存します。1件 10MB まで
- 取り込める形式：PDF、画像（JPEG・PNG・HEIC/HEIF・GIF・WebP・TIFF）、Excel（xlsx・xls）、Word（docx・doc）、ZIP、XML、CSV、テキスト。
  種類は拡張子ではなく中身で判定し、何のファイルか判定できないもの（実行ファイルなど）は受け付けません（旧形式の Office と、CSV・テキストの区別だけは拡張子も見ます）
- 画面での表示は形式ごと：PDF・画像はそのまま、CSV・XML は文字として（UTF-8 で読めなければ Shift_JIS）、Excel・Word・ZIP は表示せず「書き出して開く」。
  変換が要るときも表示のときだけ行い、保存しているファイルとハッシュは変えません
- 証憑ごとに **取引年月日・取引金額・取引先**（電子取引データの検索要件の項目）を持ちます。仕訳がまだ無い証憑も登録でき、あとから仕訳とひも付けます
- 仕訳とのひも付けは多対多（請求書1枚を分割で支払う、1つの仕訳に請求書と領収書、など）。仕訳の訂正画面から「取り込んでひも付ける」「登録済みから選ぶ」ができます
- ファイルの中身は登録後に差し替えできません（トリガーで拒否）。差し替えるときは新しく登録し、古い方を無効（通常モードでは削除）にします
- 登録時にファイルの **SHA-256** を記録します。「改ざんの確認」で、中身から計算し直したハッシュを、記録と登録時の履歴（厳密モード、書き換え不可）の両方と照らし合わせます
- 「ファイルを書き出す」で、検索結果のファイルを `取引年月日_取引先_金額_No.拡張子` の名前で一覧 CSV と一緒にフォルダへ書き出します（税務調査での「ダウンロードの求め」を想定）
- ファイルは base64 の文字列で SQLite に保存しています（画面との受け渡しが JSON のため。容量は約 1.33 倍）

## スキャナ保存（紙の証憑を読み取って保存）
令和6年1月1日以後の要件にそって確かめます。電子帳簿保存法に対応した保存方式（厳密モード）の帳簿だけで使えます
（タイムスタンプの代わりに、訂正・削除の履歴が残る仕組みで入力期間内に保存したことを確かめるため）。
- 取り込みの画面で区分を「スキャナ保存（紙を読み取ったもの）」にします。受領日（紙を受け取った日）が必須です
- **書類の区分**：重要書類（契約書・領収書・請求書・納品書など）／一般書類（見積書・注文書）。書類の種類から自動で選び、変えることもできます
- **入力期間**：事業者設定で方式を選びます（早期入力方式＝受け取ってからおおむね7営業日以内／業務処理サイクル方式＝最長2か月＋おおむね7営業日以内）。
  取り込みの画面に入力期限と残りの営業日を出します。期限を過ぎても登録はできますが「入力期間外」の印がつきます（要件を満たさないので紙の原本も保存）
- **画質**：JPEG・PNG はファイルの中身で確かめます（200dpi 以上。dpi が書かれていない写真は画素数で判断：A4 で約388万画素以上。重要書類はカラー、一般書類はグレースケールも可）。
  足りなければ取り込めません。PDF・HEIC など中身を読めない形式は「200dpi 以上・カラーで読み取った」の確認（自己申告）で取り込みます。確認の結果は取り込んだときのまま残り、書き換えられません
- **帳簿との相互関連性**：重要書類は仕訳とのひも付けが必要です。ひも付いていないものには「要ひも付け」の印がつきます
- 一覧・詳しく見る画面・CSV に、区分・入力期限・期間内か・画質が出ます。区分（電子取引・スキャナ保存）で絞り込めます

## 祝日・休業日
- 営業日は、土日・祝日・休業日を除いて数えます（スキャナ保存の入力期限など）
- **祝日**はソフトに内蔵しています（内閣府「国民の祝日」の CSV から作成。2000年〜2027年。`src/constants/holidays.ts`）。
  新しい年の分は、事業者設定の「最新の祝日を取得」で内閣府から取得できます（押したときだけ接続。取得先は Rust 側で決め打ち。取得できなくても内蔵の祝日で動く）。
  来年の祝日が無ければ画面で知らせます
- **休業日**（年末年始・お盆休みなど）は事業者設定で足せます。「年末年始（12/29〜1/3）を足す」ボタンもあります
- 取得した祝日と休業日は帳簿ファイルに保存し、変更は「訂正・削除履歴」に記録します（厳密モード）

## 取引先（任意）
- 補助科目とは別に、取引先の一覧を持ちます（同じ相手が売掛金にも外注工賃にも出てくるため）。適格請求書発行事業者の登録番号（T + 13桁）も持てます
- 仕訳1件に1つ付けられます（帳簿入力・振替伝票・仕訳の訂正画面）。1つの伝票に複数の相手が混ざる場合は、伝票を分けて入力します
- 一覧に無い名前は、入力欄の「取引先に追加」でその場で登録できます
- 証憑の取引先名が一覧の名前と同じなら、その取引先とつながります（CSV に登録番号も出ます）
- 仕訳日記帳で取引先による絞り込み、CSV に取引先・登録番号。履歴の写しには記録した時点の取引先名が残ります
- 使った取引先は削除できません（非表示にはできます）

## 改ざんの検知（厳密モード）
帳簿ファイルは普通の SQLite なので、ソフトを通さずに書き換えること自体は**防げません**（トリガーも消せます）。
また、ソースコードを公開しているため、ソフトの中に秘密の鍵を隠して守る方法も使えません。そこで「できるところまで検知する」方針にしています。

1. **記録の連鎖（ハッシュチェーン）**：履歴を1件書くたびに、1つ前の記録のハッシュを含めたハッシュを `audit_chain` に積みます。履歴を書き換え・削除すると、そこから先が合わなくなります
2. **今の中身との照合**：仕訳・証憑・期首残高・締めについて、最後に記録した状態のハッシュと今の中身を比べます。履歴を残さずに直接書き換えたものが見つかります
3. **トリガーの見張り**：前回開いたときにあったトリガーが消されていたら、記録して知らせます（トリガーは開くたびに作り直すため、黙って元に戻さないように）
4. **確認コード（外部の控え）**：連鎖をまるごと計算し直されると 1・2 では見抜けません。年度を締めたときの確認コード（連鎖の先頭のハッシュの一部）を、決算書の控えなど帳簿ファイルの外に残しておけば、あとで照らし合わせて見つけられます。
   確実にしたい場合は、書き出した確認コードのファイルに**有料のタイムスタンプ**を付けてください

帳簿を開くたびに軽い確認（1〜3）を行い、問題があれば画面上部で知らせます。「訂正・削除履歴」の「改ざんの確認」では、証憑ファイルの中身も含めて確かめ、確認コードの書き出し・照合ができます。
この仕組みを入れる前に作った帳簿は、最初に開いたときの状態を「基準点」として連鎖を始めます（それより前の改ざんは見つけられません）。

## ユーザー
- 帳簿を使う人を登録し、「誰が操作したか」を記録します
- 権限は3つ：**管理者**（すべて）・**入力担当**（仕訳・証憑・取引先・定型仕訳・CSV 取り込みなど日々の入力。設定・勘定科目・期首残高・ユーザーの管理は不可）・**閲覧のみ**（見るだけ）
  - 最初のユーザーと、権限を入れる前からいたユーザーは管理者。追加したユーザーの既定は入力担当
  - 権限を変えられるのは管理者だけ。使える管理者が1人もいなくなる変更はできない。自分のパスワードはどの権限でも変えられる
  - 権限は画面だけでなく、書き込みの入り口（repo.ts の tx）でも確かめる。権限の変更は履歴に残る（厳密モード）
- 帳簿を開くときに使う人を選びます。ユーザーが1人だけでパスワードもなければ、選ぶ画面は出ません（最初のユーザーは帳簿の持ち主の氏名で自動で作ります）
- パスワードは任意です（PBKDF2-SHA256 のハッシュで保存）。変更・解除には今のパスワードが要ります
- ログアウトは、「帳簿を閉じる」「ユーザーの切り替え」と、ウィンドウを閉じたとき（⌘Q を含む）に記録します。強制終了などで記録できなかったログインは、利用の記録に「ログアウトの記録なし」と出ます
- 操作者が残るところ：訂正・削除履歴（仕訳・科目など・証憑）、仕訳と証憑の登録者・最終更新者、利用の記録（ログイン・ログアウト）。厳密モードでは記録の連鎖にも入ります
- 履歴に名前が残るので、ユーザーは削除できません（非表示にはできます）

## 帳簿ファイルの暗号化（任意）
- 事業者設定の「帳簿ファイルの暗号化」で、帳簿ファイルにパスワードをかけられます（管理者のみ。8文字以上）。かけない使い方もそのままできます
- ファイル全体を SQLCipher の形式で暗号化します（ページごとに AES-256。改ざん検知の HMAC つき）。パスワードがないと中身を読めず、このソフトの外から書き換えることもできません
- 鍵はパスワードとファイルごとのソルトから Argon2id で作ります
- **回復キー**：暗号化したときに表示します（コピー・ファイルに保存できる）。パスワードを忘れても、開くときに「パスワードを忘れたとき（回復キーで開く）」から入れれば開けます。回復キーは鍵そのもので、パスワードを変えると新しくなります
- **この PC に記憶する**：開くとき・暗号化するときに選ぶと、鍵を OS の鍵の保管庫（macOS のキーチェーン、Windows の資格情報マネージャー）に預け、次からこの PC ではパスワードを聞かずに開きます。ファイルだけを持ち出したときは、ほかの PC ではパスワードを聞かれます。記憶は事業者設定で消せます
- パスワードの変更・暗号化をやめるには、今のパスワード（または回復キー）が要ります。かけた・変えた・やめたことは履歴に残ります（厳密モード）
- 暗号化した帳簿のバックアップ（.dmbk）も暗号化されたままです。パスワードを変えたあとも、それより前のバックアップは当時のパスワード（回復キー）で開きます
- かける・やめるときは、暗号化した（外した）写しを同じフォルダに作ってから置き換えます。途中で止まっても元のファイルは残ります
- 暗号化はパスワードを知らない人から守るものです。パスワードを知っている人による書き換えは、厳密モードの履歴と記録の連鎖で「わかる」ようにしています

## 保存とトランザクション
- 書き込みはすべてトランザクションの中で行います（`repo.ts` の `tx`）。途中で失敗したり、ソフトが強制終了したりしても、SQLite が書きかけを丸ごと取り消します
- 書き込みの前に「保存中」の目印（`pending_ops`）を置き、終わったら消します。目印が残っていたら、次に開いたときに「前回、次の保存が完了しませんでした（取り消されています）」と知らせ、厳密モードでは検知の記録に残します

## 帳簿の保存方式（電子帳簿保存法モード）
帳簿を作るときに次のどちらかを選びます。**対応 → 通常 には戻せません**（DB のトリガーで拒否）。

通常で作った帳簿は、**翌年への繰越のときだけ**、翌年から「電子帳簿保存法に対応」へ切り替えられます。
- 確認が出るのは、通常モードの帳簿で、翌年以降の仕訳がまだ無いとき（その年の初めから履歴を残せるとき）だけです
- 切り替えると、その時点の帳簿を基準点にして記録の連鎖を始めます。対応を始めた年（`strict_from_year`）と切り替えた日時を残し、切り替えたことを履歴に記録します
- **対応外の年を目立たせます**：サイドバーに「○年は電子帳簿保存法の対応外」、年度の選択に「（電帳法の対応外）」、その年を開いている間は画面上部にお知らせ、決算書の見出しに「電子帳簿保存法の対応外（通常の保存）」。事業者設定の保存方式には「○年まで 通常／○年から 対応」と出します

| | 電子帳簿保存法に対応（優良な電子帳簿） | 通常 |
|---|---|---|
| 仕訳の訂正 | 訂正前・訂正後を履歴に記録（理由も任意で） | 上書き |
| 仕訳の削除 | 「削除済み」の印をつけ、内容を履歴に記録（伝票番号は欠番） | 完全に削除 |
| 勘定科目・補助科目の名前変更 | 表示中の年度から新しい名前。過去の年度は元の名前のまま。履歴に記録 | すべての年度に反映 |
| 勘定科目・補助科目の追加・非表示・削除 | 履歴に記録 | 記録しない |
| 期首残高の変更（繰越処理を含む） | 変更前後の金額を履歴に記録 | 記録しない |
| 年度の締め・締めの解除 | 履歴に記録（解除には理由が必須） | 締め・解除はできるが、記録しない |
| 証憑の訂正 | 訂正前後を履歴に記録（理由は必須） | 上書き |
| 証憑の削除 | 「無効」の印をつける（ファイルと履歴は残る。理由は必須） | 完全に削除 |
| 証憑と仕訳のひも付け・解除 | 履歴に記録 | 記録しない |
| 取引先の追加・変更・非表示・削除 | 履歴に記録 | 記録しない |
| 操作したユーザー | 履歴のすべてに記録 | 仕訳・証憑の登録者・最終更新者のみ |
| 改ざんの検知（記録の連鎖・確認コード） | あり | なし（証憑ファイルのハッシュ確認のみ） |
| 「訂正・削除履歴」画面 | あり | なし |

厳密モードの仕組み
- 仕訳は物理削除しない。登録・訂正・削除のたびに、その時点の仕訳の写し（科目名はその年度の名前）を `entry_history` に積み上げる
- 科目・補助科目の名前は `master_names` に「何年から何という名前か」で持つ
- より新しい年度がある状態で、過去の年度の名前は変えられない
- 科目などの変更は `master_history` に記録
- `entry_history` / `master_history` は SQLite のトリガーで UPDATE / DELETE を禁止。削除済みの仕訳も変更不可
- **限界**：SQLite ファイルを外部ツールで直接編集すること自体は防げない。ソフトとして保証できる範囲と、
  法令上の保存要件との差は、研究上の論点として残している（下の「足りていないところ」参照）
- **消費税**：免税事業者（税込経理）のみ。課税区分・経理方式・税区分は画面にあるが、グレーで選べない状態

## 科目と補助科目
- 勘定科目は区分ごとのコード範囲で追加できます（資産 100〜199、負債 200〜299、資本 300〜399、
  収益 400〜499、売上原価 500〜599、経費 600〜699、専従者給与等 700〜799）→ 1区分あたり最大100科目
- 初期科目は削除・区分変更・コード変更できません（名前は変更可）
- 現金・事業主貸・事業主借・元入金は、仕組み（繰越・家事按分・帳簿入力）で使うため非表示にもできません。名前は変えられます（例：現金 → 現金預金。プログラムは名前ではなくコードで探しています）
- 追加した科目でも、使用済み（仕訳・期首残高・家事按分の設定のどれかで使っている）なら削除できません（非表示にはできます）
- 補助科目は1科目あたり100件まで

## 開発方針
- **個人・法人は1つのソフトで扱う**：将来は、帳簿を作るときに「個人／法人」を選ぶ（保存方式と同じく、あとから変更不可）
- **法人対応までに守ること**（あとで大きな作り直しをしないため）
  - 会計期間の開始日・終了日は、必ず `lib/accounting.ts` の `yearStart` / `yearEnd` を通す（日付を直接 `1月1日`・`12月31日` と書かない）
  - 個人特有の処理（元入金の再計算、事業主貸・事業主借の扱い、青色申告特別控除）は1か所にまとめ、「個人の場合の処理」として分けておく
  - 決算書・試算表の見出し（「資本」「元入金」など）は画面に直接書かず、区分の定義（`constants/accounts.ts`）から引く

```
src/

```

## データファイル
- `書類/domble/*.dmbl` が帳簿ファイル（1ファイル = 1事業者、複数年を保存）
- 開くたびに `書類/domble/Backup/` へ `.dmbk` として自動バックアップ（事業者設定で決めた世代数を超えたら古いものから消す。既定 100）
- バックアップ（`.dmbk`）は **読み取り専用** で開きます。ファイルを読み取り専用で開いて中身をメモリに写し、その写しを表示するので、元のファイルには一切書き込みません（古い形式の列の追加も写しにだけ行う）。
  登録・訂正などはすべて止め、年度の切り替えだけできます。開いたときの記録（ログイン・連鎖の開始・締めの初期化・バックアップの整理など）も行いません
- バックアップの中身を今の帳簿に戻す機能はまだありません（必要なら、バックアップをコピーして拡張子を `.dmbl` に変えて開く）
- 証憑のファイルも帳簿ファイルの中に入るので、1ファイルを持ち運べばすべてそろう
- 暗号化した帳簿ファイルは、パスワード（または回復キー）がないと開けません（「帳簿ファイルの暗号化」を参照）
