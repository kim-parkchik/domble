## 特長
- **手元で完結**：インターネットもアカウントも要りません。帳簿は1つのファイル（.dmbl）で、証憑もまとめて持ち運べます
- **電子帳簿保存法（優良な電子帳簿）に対応**：訂正・削除の履歴、改ざんの確認、届出の案内まで
- **日々の記帳から決算書まで**：出納帳の形の入力、家事按分、固定資産台帳と減価償却、青色申告決算書（4ページ）
- **守りもしっかり**：自動バックアップ、帳簿ファイルの暗号化（任意）、ユーザーごとの権限、月・年度の締め

## 技術スタック
- Runtime: Bun / Framework: Tauri 2 / Frontend: React + TypeScript
- Icons: Lucide React / Database: SQLite（Rust 側の rusqlite。接続は帳簿ファイルごとに1本で、トランザクションを使う。暗号化のため SQLCipher 入りでビルドする）

## 使い方
```
bun install
bun tauri dev     # 開発モードで起動
bun test          # 会計ロジックのテスト
```

## 締め（月・年度）
- 年度ごとに**「何月まで締めたか」**を持ちます（`fiscal_closings.period_end` = 締めた月の末日）
  - **月の締め**：締めた月までの仕訳（登録・訂正・削除）は変更できません。通帳と照らし合わせた月、確認が済んだ月などを締めておくと、うっかり変えてしまうのを防げます
  - **年の締め**（12月まで締める）：期首残高・家事按分・減価償却・その年度の科目名、その年に使っている固定資産の台帳なども変更できません。厳密モードでは確認コードを出します
- 事業者設定の「締め（月・年度）」で、年度ごとに「○月まで」を選んで締めます。直すときは「締めを戻す」で、**どの月までの締めに戻すかを1回選ぶだけ**です（年の締めから「10月まで」に戻せば、11・12月だけ直せる）。締めと戻しは管理者だけ。厳密モードでは戻す理由が必須で、締めと戻しは履歴に「9月まで締め → 締めなしに戻す（理由：…）」のように残ります（毎回「編集しますか？」と聞く方式は、反射的に「はい」を押されやすいため採っていません）
- 翌年への繰越は「翌年を始める」だけで、前の年は締めません（**「この年を締める」**にチェックしたときだけ年の締めをする。最初はチェックなし）。前の年の決算を直しながら翌年の入力を始められます。直したら繰越をやり直します（ずれは画面上部で知らせる）
- 前の年度を直して、翌年の期首残高が繰越額とずれたときは、画面上部でお知らせし、繰越のやり直しを促します
- 繰越をせずに新しい年を始めた（前の年に年末の残高があるのに、その年の期首残高が1つも無い）ときも画面上部で知らせ、「○年から繰り越す」で前の年の繰越の欄を開きます（`useMissingCarry`）。
  画面上部の年の切り替えの最後の「＋ ○年を始める（繰越）」からも開けます。年は事業者設定では変えません（「会計年度」の欄は帳簿を作るときの「帳簿を始める年」だけ）
- 締めは画面だけでなく、DB のトリガーでも確認しています（締めた月への仕訳の書き込み、年の締めをした年度の期首残高などへの書き込みを拒否）
- この仕組みを入れる前に作った帳簿は、開いたときに一度だけ、繰越済みの年度を年の締めにします
- 「何年から」で持つ設定（消費税・申告の種類・家事按分・科目名（厳密モード）・決算書の欄・不動産所得の規模・固定資産の事業専用割合）は、締めた年が引き継いでいる設定を変えられません（前の年を締めずに次の年を締めたとき。変えると締めた年の設定まで変わるため）。
  画面・repo（`lib/closing.ts` の `inheritingClosedYears`）・DB のトリガーで止めます。値の変わらない保存は何もしません（その年の行を足すと、締めた年の引き継ぎ元が変わるため）

## 決算整理
- 「決算整理」の画面に、決算でやることを順に並べ、それぞれの状態（作成済み・未作成・計算と違う・対象なし）と入口を出します（決算・申告の手順の案内も兼ねる。`features/reports/YearEndPage.tsx`）
  - 決算の前（未登録の明細の件数・消費税の確認の件数（課税事業者）・期首残高（繰越していない・前年の残高とずれ・貸借が合わない））と、
    決算のあと（決算書・消費税の申告（翌年3月31日）・所得税の確定申告（翌年3月15日。土日・祝日なら次の平日。`lib/deadlines.ts`）・年の締めと確認コードの控え・翌年への繰越）も同じ一覧に出します。
    期限が30日以内なら残りの日数、過ぎていて締めていなければ目立たせます
  - ホームの「次にやること」には、未登録の明細・消費税の確認の件数と、12月からは決算と申告の期限、年が明けて繰越がまだなら繰越を出します（押すとその画面へ）
- **棚卸**：棚卸表（品名・数量・単価。金額は 1円未満切り捨て）か期末の棚卸高を年ごとに保存し（`inventory_counts`。CSV・印刷）、「期首商品棚卸高 ／ 棚卸資産（期首の棚卸高＝帳簿の期首残高）」「棚卸資産 ／ 期末商品棚卸高」の決算整理仕訳を1本作ります（`lib/yearEnd.ts`）。
  期首商品棚卸高が棚卸資産の期首残高と違う（期首の振替の漏れ・二重）、棚卸資産の期末残高が期末商品棚卸高と違う、を知らせます
- **未払消費税等**（課税事業者の年）：その年の課税区分で計算した申告書の ㉖（中間納付を差し引いた後）から、「租税公課 ／ 未払消費税等」（還付なら「未収入金 ／ 雑収入」。どちらも対象外）の決算整理仕訳を作ります。
  税込経理で、納付税額を未払計上した年の必要経費にするとき（国税庁 No.6901）。中間納付は納めたときに租税公課、翌年に納めたら「未払消費税等 ／ 普通預金」と案内します
- 棚卸・未払消費税等の仕訳は、ほかの決算整理と同じく年度・種類ごとに1本（`year_end_runs`）で、作り直すと同じ仕訳を訂正します
- **振り戻し**：決算整理仕訳（台帳・家事按分・貸倒引当金・棚卸・未払消費税等から作ったものを除く）を開くと、「翌年1月1日付で振り戻す」で貸借を入れ替えた仕訳を作れます（1回だけ。`entry_reversals`）。未払費用・前払費用など向け

## 決算整理仕訳
- 仕訳に「決算整理」の印を持てます（振替伝票・仕訳の訂正画面の「決算整理仕訳」、帳簿入力で「決算整理」を選んで入力）。日付は年度末（12月31日）だけです
- 帳簿入力では、12月のあとの「決算整理」に出ます（12月を選んでも決算整理仕訳は出ない）。残高の推移でも、年度末のほかの仕訳よりあとに並びます
- 家事按分の年末の振替（年度末の日付）も決算整理仕訳になります
- 仕訳日記帳・CSV（「決算整理」の列）にも印が出ます。CSV 取り込みでも「決算整理」の列に何か入っていれば決算整理仕訳です
- 厳密モードでは、履歴の写しと記録の連鎖にも印が入ります（印の無い仕訳の記録は今までと同じハッシュ）

## 固定資産台帳・減価償却
- 10万円以上の備品・車・建物などを登録すると、年度ごとの減価償却費を計算します（計算は `lib/depreciation.ts`）
  - **定額法**（平成19年4月1日以後に取得したもの）：取得価額 × 償却率 × 使った月数 / 12（1円未満は切り上げ）。償却率は 1/耐用年数 を小数第3位で切り上げたもの。最後は 1円（備忘価額）を残す
  - **旧定額法**（償却方法「定額法」で、取得日が平成19年3月31日以前のもの。取得日で自動で決める。国税庁 No.2105）：取得価額 × 90% × 旧定額法の償却率（耐用年数省令 別表第七。2〜100年）× 月数 / 12。償却費の累計が取得価額の95%に達したら、その翌年から5年間で1円まで均等に償却する（{取得価額 − 取得価額 × 95% − 1円} ÷ 5 × 月数 / 12）。台帳・決算書の償却方法は「旧定額法」、決算書の償却の基礎になる金額は取得価額 × 90%（均等償却の年は取得価額 × 5%。償却率は 0.200、摘要に「均等償却」）。登録の画面でも知らせる
  - **200%定率法**（償却方法の届出をした人。平成24年4月1日以後に取得したもの。国税庁 No.2106）：期首の未償却残高 × 定率法の償却率（調整前償却額）。償却保証額（取得価額 × 保証率）に満たなくなった年から、改定取得価額（その年の期首の未償却残高）× 改定償却率。月割り・1円未満切り上げ・1円（備忘価額）まで。
    償却率・改定償却率・保証率は耐用年数省令 別表第十（2〜100年）。建物、平成28年4月1日以後に取得した建物附属設備・構築物、ソフトウェアには使えない。domble を使う前から持っている資産は、期首の未償却残高の年から改定の判定をする
  - **一括償却資産**（10万円以上20万円未満）：1/3 ずつ3年。月割りしない。売却・除却しても3年続ける
  - **少額減価償却資産**（青色申告。取得日が令和8年3月31日までは 30万円未満、令和8年4月1日〜令和11年3月31日は 40万円未満。それより後の取得は特例なし）：使い始めた年に全額。1年の合計が300万円を超えると知らせる
  - **繰延資産（任意償却）**（開業費など）：年ごとに償却する額を決める（`asset_amortizations`。決めていない年は60か月の均等償却を月割り）。0円まで償却する。決算書の減価償却費の計算に「任意償却」として書く
- **耐用年数**：「耐用年数表から選ぶ」で、主な資産（耐用年数省令 別表第一・第三から。`constants/assetLives.ts`）の耐用年数と科目を入れられます。
  中古資産は簡便法で出せます（法定耐用年数の全部を経過：法定 × 20%、一部を経過：（法定 − 経過）＋ 経過 × 20%。月数で計算し、1年未満切り捨て、2年未満は2年。国税庁 No.5404）
- **事業専用割合**は資産ごとに、年ごとに持ちます。償却費のうち事業分（1円未満切り捨て）を減価償却費、残りを事業主貸にします（未償却残高は償却費の全額だけ減る）
  - 家事按分と同じく「何年から何%」で持ちます（`asset_rates`。使い始めた年からの割合は `fixed_assets.business_rate`）。資産の画面で割合を変えると、表示中の年からの割合になり、前の年の割合はそのまま残ります（前の年と同じ割合に戻すと、その年の行は消す）
  - 台帳・決算書（減価償却費の計算）・年末の仕訳は、その年の割合で計算します
- **年の締め**：年の締めをした年に台帳に出る資産（使い始めた年から売却・除却の年まで。一括償却資産は除却しても3年目まで。売っていなければその先ずっと）は、
  売却・除却の日（締めた年の台帳が変わらないもの）と、締めていない年からの事業専用割合だけ変えられます。追加・削除・ほかの項目（名称・備考も）の変更、締めた年の割合が変わる変更は、画面・repo（`lib/depreciation.ts` の `assetLockError`）・DB のトリガーで止めます。直すときは締めを戻します
- 年末に「減価償却費（事業分）＋事業主貸（家事分） / 資産の科目」の決算整理仕訳（12月31日付）を1本作ります。台帳を直したら「作り直す」で同じ仕訳を訂正します（作成済みの仕訳と計算が違えば知らせる）
- 資産を買った仕訳は振替伝票で入れます。資産の科目ごとに、帳簿の期末残高と台帳の未償却残高を並べて照合できます
- domble を使う前から持っている資産は、「その年の期首の未償却残高」から計算を始められます
- 売却・除却した日を入れると、その月まで償却します。売却か除却か（売却なら売却した額（税込））も入れ、台帳の「売却・除却の仕訳」で、売却・除却した日付の仕訳を作ります（`lib/depreciation.ts` の `disposalLines`。作り直すと同じ仕訳を訂正する。定額法の資産だけ）
  - 売却：受け取った科目 ／ 資産の科目 を売却額で（課税売上 10%。簡易課税は第4種。家事と兼用する資産は事業用の部分だけ課税売上）。帳簿価額（売った年の期末の未償却残高）との差は、資産の科目 ／ 事業主借（益）か 事業主貸 ／ 資産の科目（損）。個人の事業用資産の売却損益は事業所得ではなく譲渡所得のため
  - 除却：固定資産除却損（家事分は事業主貸。不動産所得の資産は雑費（不動産）） ／ 資産の科目 を帳簿価額で
  - その年の減価償却費は、年末の減価償却の仕訳で売却・除却した月まで計算する（売却・除却の仕訳と合わせて、資産の科目が 0 になる）
- 台帳の追加・変更・削除は履歴に残り、記録の連鎖と今の中身との照合に入ります（厳密モード）。減価償却費は家事按分の画面ではなく、ここで資産ごとに割合を決めます（台帳から作った仕訳は、家事按分の年末の振替の計算に入れない）
- 科目に「構築物」「一括償却資産」「ソフトウェア」を足しました（既存の帳簿にも開いたときに入る）
- 開業費（繰延資産。160）の科目があります。台帳に「繰延資産（任意償却）」で登録すると、年ごとに償却する額を決めて償却できます

## 不動産所得
- 1つの帳簿で事業所得と不動産所得を分けます。**損益の科目（収益・売上原価・経費・専従者給与等）ごとに所得の区分**（事業所得／不動産所得。`accounts.income_kind`）を持ち、預金・事業主貸借・元入金などの貸借対照表の科目は共通です（考え方は `lib/incomeKind.ts`）
- 事業者設定の「不動産所得」で、なし／あり（事業的規模でない）／あり（事業的規模：おおむね5棟10室以上など）を選びます。年ごとに持ち（`real_estate_years`。表示中の年から、次に変えた年の前まで）、前の年の規模はそのまま残ります。「あり」にすると、非表示で入っている不動産所得の初期科目を表示します：賃貸料（460）・礼金・権利金・更新料（461）・名義書換料その他（462）、租税公課・損害保険料・修繕費・減価償却費・借入金利子・地代家賃・給料賃金・貸倒金（いずれも「（不動産）」。660〜667）・雑費（不動産）（698）・専従者給与（不動産）（760）。科目を足すときも、損益の科目なら所得の区分を選べます（あとから変えられない）
- 固定資産は資産ごとに所得の区分を持ち、不動産所得の資産は年末の減価償却の仕訳を減価償却費（不動産）にします（事業専用割合は貸付割合として使う）
- 一般用の決算書・収支内訳書は事業所得の科目だけで作ります。貸借対照表は帳簿全体で、「青色申告特別控除前の所得金額」は事業所得と不動産所得を合わせた額（事業所得がある人は一般用の決算書に貸借対照表を書く）
- **青色申告特別控除**は不動産所得、事業所得の順に差し引きます（決算書2ページの ⑥ 不動産所得 → ⑧ そこから差し引く額 → ⑨ 残りを事業所得から）。事業所得が無く、不動産の貸付けが事業的規模でなければ 10万円まで
- **所得税**：第一表の ㋒（収入金額）・③（所得金額）、(58) 専従者給与に不動産所得の分（事業的規模の青色申告だけ必要経費。それ以外は所得に戻して知らせる）、(59) 青色申告特別控除額の合計、第二表の「不動産所得から差し引いた青色申告特別控除額」。赤字のうち、土地等を取得するために要した負債の利子の額（不動産所得用の決算書に書き込む）までは損益通算しない（③ は 0 か差額）
- **不動産所得用の決算書**（決算書の画面で「事業所得（一般用）／不動産所得用」を切り替える。計算は `lib/realEstateStatement.ts`）
  - 青色申告決算書（不動産所得用）：1ページ 損益計算書（① 賃貸料 ② 礼金・権利金・更新料 ③ 名義書換料その他、⑤〜⑪ 租税公課・損害保険料・修繕費・減価償却費・借入金利子・地代家賃・給料賃金、⑫〜⑯ 追加の欄、⑰ その他の経費、⑲〜㉓）、2ページ 不動産所得の収入の内訳・給料賃金・専従者給与の内訳、3ページ 減価償却費の計算（貸付割合）・地代家賃・借入金利子の内訳、4ページ 貸借対照表（事業所得が無いときだけ）
  - 収支内訳書（不動産所得用）：1ページ 収支（①〜⑤、⑥〜⑩、㋑〜㋭、⑪〜⑮）・不動産所得の収入の内訳・給料賃金の内訳、2ページ 減価償却費・借入金利子・修繕費・地代家賃の内訳、貸付不動産の保有状況、特殊事情
  - 科目は「（不動産）」を除いた名前で欄に当て（火災保険料 → 損害保険料、支払利息 → 借入金利子 などの言い換えも）、当たらない経費は追加の欄（青色 5・白色 1）、あふれたらその他の経費・雑費にまとめて知らせる
  - 収入の内訳は賃借人（仕訳の取引先、無ければ補助科目）ごとに、帳簿から賃貸料（年額）・礼金等・名義書換料その他を出し、貸家・貸地等の別・用途・所在地・契約期間・面積・月額・保証金は書き込み。賃借人の分からない分は最後の1行
  - 土地等を取得するために要した負債の利子の額も、1ページで書き込む（所得税の ③ に使う）
- **e-Tax 用のデータ**：青色は KOA220（1〜4ページ。4ページの貸借対照表は事業所得が無いときだけ）、白色は KOA130（1・2ページ）。事業所得が無ければ一般用（KOA210・KOA110）は書かない。礼金・権利金・更新料は収入の内訳の「礼金」の欄にまとめて書き、書き出すときに知らせる。国税庁の XSD に照らすテストで、青色・白色と事業所得のあり・なしの4通りを確かめています
- 扱わないもの：白色申告の年の不動産所得の事業専従者控除、不動産所得の税理士等の報酬の内訳、国外中古建物の不動産所得の特例、組合事業の不動産所得の損失

## 申告の種類（年度ごと）
- 青色申告（65万円・55万円・10万円控除）か白色申告かを、事業者設定で**年ごとに**決めます（`filing_years`。考え方は `lib/filing.ts`）。決めた種類は次に変える年まで引き継ぎ、設定の無い年は帳簿を作ったときの種類です。開業の年は白色、承認を受けた翌年から青色、のように変えても、前の年の決算書は前の年の種類のままです
- その年の種類で変わるもの：決算書の形（青色申告決算書・収支内訳書）、所得税の事業所得（青色申告特別控除・事業専従者控除）、e-Tax 用のデータの様式、少額減価償却資産の特例（事業に使い始めた年が青色のときだけ）、電子帳簿保存法の画面の優遇措置
- 年の締めをした年の種類は変えられません（締めた年が引き継いでいる前の年の設定も）。白色にする年に使い始めた資産に少額減価償却資産の特例を使っていれば、白色にできません。変更は履歴に残ります（厳密モード）

## 決算書（1〜4ページ）
- **様式の欄・番号**：1ページの損益計算書（① 売上（収入）金額 〜 ⑦、経費 ⑧〜㉛（追加の欄 ㉕〜㉚）・㉜ 計・㉝、繰戻額等 ㉞〜㊲、繰入額等 ㊳ 専従者給与〜㊷、㊸ 青色申告特別控除前の所得金額・㊹・㊺）と、4ページの貸借対照表（資産負債調）・製造原価の計算（①〜㉖）を、令和7年分の様式と「決算書の書き方」の欄と番号で出します（行は `lib/statementForm.ts`）。
  科目は勘定科目の「決算書の欄」（`lib/statementLines.ts`）で欄に入れ、欄の名前と違う科目は画面にだけ小さく添えます。使っていない追加の欄も番号だけの空欄で並べます
- **見出し**（1ページ）：住所・事業所所在地・電話番号（自宅・事業所）・業種名・屋号・氏名・加入団体名・依頼税理士等（事業者設定と e-Tax の申告者の情報から）と、事業期間（所得税の入力の「事業税に関する事項」の年の中途の開業・廃業から）
- **製造原価の計算**（4ページ下）：売上原価の科目のうち、「決算書の欄」で製造原価の欄（期首・期末の原材料棚卸高、原材料仕入高、労務費、外注工賃・電力費・水道光熱費・修繕費・減価償却費・雑費と追加の欄 8 つ、期首・期末の半製品・仕掛品棚卸高）を選んだもの（名前で自動でも）から作り、㉖ 製品製造原価を1ページの ③ 仕入金額（製品製造原価）に足します。
  製造原価の初期科目（コード 520〜531。外注工賃（製造）など）は初めは非表示で、事業者設定の「製造原価」を「使う」にするとまとめて表示します。「使わない」にも戻せます（締めていない年にそれらの科目の仕訳があるときは戻せない。記帳中の科目が隠れて入力できなくなるため）。
  表はその年に製造原価の科目に金額があるか（または使っているか）で出すので、戻しても締めた年の決算書は変わりません。使っていないあいだは、勘定科目の「決算書の欄」に製造原価の欄を出しません。e-Tax 用のデータ（AMH）にも書きます
- **まとめて印刷**：1〜4ページを続けて印刷します（「印刷」は表示中のページだけ）
- 金額は帳簿から出します（集計は `lib/statements.ts`）
  - **月別売上（収入）金額及び仕入金額**：家事消費等・雑収入を除く収益の科目を月ごとに、仕入金額の欄の売上原価の科目（仕入高・外注加工費など）と製造原価の原材料仕入高を月ごとに集計（製造原価が無ければ計は1ページの ③ と同じ）。家事消費等・雑収入は年間で
  - **給料賃金・専従者給与・利子割引料・地代家賃・税理士等の報酬の内訳**：支払先ごと。支払先は、仕訳の取引先 → 明細の補助科目 → どちらも無ければ「支払先の指定なし」の順で決める（人ごとに補助科目を作っておくと分かれる）
  - 家事按分している科目は、本年中の支払額（家事分を含む）と必要経費算入額（事業分）を分けて出す
  - **売上（収入）金額・仕入金額の明細**（3ページ）：仕訳の取引先（無ければ補助科目）ごとに、金額の多い順に4件と「上記以外」。売上は家事消費等・雑収入を除く収益の科目、仕入は決算書の「仕入金額」の欄の科目と製造原価の原材料仕入高。登録番号は取引先の登録番号（登録番号を書いた相手は名前と所在地を省略できる）、所在地は書き込み。計は1ページの売上（収入）金額と、2ページの月別の仕入金額の計（売上の上記以外には家事消費等・雑収入も入る）
  - **減価償却費の計算**：固定資産台帳から（少額減価償却資産は摘要に「措法28の2」）
  - **貸倒引当金繰入額の計算**（2ページ。計算は `lib/allowance.ts`。国税庁「青色申告の決算の手引き」Ⅶ）：② 年末の一括評価による貸金の合計額は、売掛金・受取手形・貸付金・未収入金の年末の残高に「足し引きする額」を書き込んで出す（家事上の貸金・保証金・敷金・手付金・前渡金・仮払金・立替金・同じ相手の買掛金と相殺できる額・個別評価の相手の分を引き、割り引いたり裏書譲渡したりした手形を足す）。③ 繰入限度額は ② × 5.5%（「金融業」に印を付ければ 3.3%。1円未満切り捨て）。④ 一括評価の繰入額は空なら限度額（限度額を超える額は限度額にして知らせる）。① 個別評価による繰入額は額を書き込むだけ。⑤ ＝ ①＋④
    - 「仕訳を作る」で、12月31日付の洗替の決算整理仕訳（「貸倒引当金 / 貸倒引当金戻入」期首の貸倒引当金、「貸倒引当金繰入 / 貸倒引当金」⑤）を作る。年度ごとに1本で、作り直すと同じ仕訳を訂正する（`allowance_runs`。締めた年度は作れない）。帳簿の繰入・戻入が計算と違えば知らせる
    - 1ページの損益計算書は「各種引当金・準備金等」を繰戻額等（貸方の科目：貸倒引当金戻入など。所得に足す）と繰入額等（借方の科目：専従者給与・貸倒引当金繰入など。所得から差し引く）に分ける。e-Tax 用のデータにも ①〜⑤ と1ページの欄を書く
    - 白色申告の年は一括評価を使えない（個別評価だけ）。収支内訳書には欄が無いので、繰入は経費、戻入はマイナスの経費として追加の欄に書いて知らせる
  - 税理士・弁護士等の報酬は、支払手数料の支払先から「書く」にチェックしたものだけ。利子割引料は金融機関の分のチェックを外す（印刷に出ない）
- 帳簿から出せない項目（年齢・従事月数・賞与・源泉徴収税額・続柄・支払先や売上先・仕入先の所在地・賃借物件・権利金等・借入金の残高・資産の数量・特殊事情）は、決算書の画面でそのまま書き込みます。年度ごとに保存し（`statement_notes`）、締めた年度は変えられません。帳簿そのものではないので履歴には残しません

## 収支内訳書（白色申告）
- 白色申告の年は、決算書の画面が収支内訳書（一般用）の形になります（計算は `lib/whiteStatement.ts`。令和7年分の様式・書き方）
  - 1ページ：収入金額（①売上（収入）金額・②家事消費・③その他の収入）、売上原価、経費（様式の並び。科目名で書く欄は5つで、多ければ金額の小さい科目を雑費にまとめて知らせる）、⑲専従者控除前の所得金額・⑳専従者控除・㉑所得金額、給料賃金の内訳、税理士・弁護士等の報酬・料金の内訳、事業専従者の氏名等
  - 2ページ：売上（収入）金額・仕入金額の明細（計は①・⑥）、減価償却費の計算、地代家賃・利子割引料の内訳、特殊事情。明細の表と書き込みは青色申告決算書と同じ
  - 貸借対照表はありません（白色申告では作らない）
- **専従者給与は必要経費になりません**（所得税法56条・57条）。専従者給与の科目に記帳していても経費に入れず、知らせます（家族への支払いは事業主貸で記帳する）。ほかの「専従者給与等」の科目（引当金の繰入額など）は経費の空欄に書きます
- **事業専従者控除**：所得税の画面の配偶者・扶養親族で「専従者」に印を付けた人が事業専従者です。従事月数と従事の程度・仕事の内容も、所得税の画面の「事業専従者（白色申告）」で入れます
  - 1人につき、86万円（配偶者以外は50万円）と ⑲ ÷（事業専従者の数＋1）の少ない方（1円未満切り捨て。⑲が0以下なら0）
  - 対象：12月31日に15歳以上（1月1日生まれは前の年の12月31日に年齢が上がる）で、その年に6か月を超えて事業に専ら従事した人（年の中途に開業・廃業したときは、事業の期間の2分の1を超えて）。当てはまらない人・生年月日や従事月数が入っていない人は、数に入れずに理由を出します
  - 所得税の事業所得は ①＝㉑、(58) 専従者給与（控除）額の合計額 ＝ ⑳。第二表の事業専従者に関する事項には、従事月数・程度・仕事の内容と控除額を書きます

  - **前の年の申告から引き継ぐ**：前の年に保存した所得税の入力と、その年の帳簿から前の年の計算をし直して、翌年に繰り越す額（Ⓒ と (82)）を出します。前の年も「引き継ぐ」なら、手で入れた年か入力の無い年までさかのぼります。前の年の入力が無ければ、手で入れるよう知らせます
  - 前年も青色申告なら選べる「繰戻し還付」（純損失の金額の繰戻しによる還付請求書）は作れません（赤字の年に知らせる）

- **e-Tax 用のデータ（.xtx）**：確定申告書（第一表・第二表。第四表を使う年は第四表（一）（二）も）と青色申告決算書（一般用の1〜4ページ）を1つのファイルに書き出します。白色申告の年は青色申告決算書の代わりに収支内訳書（一般用の1・2ページ）を書きます（`lib/incomeTaxXtx.ts`。決算書の数字は `lib/blueStatement.ts`・`lib/whiteStatement.ts` で、決算書の画面と同じ集計と書き込みから）。e-Taxソフト（WEB版）の「作成済みデータの利用」で読み込んで送信します
  - 手続 RKO0010。手続の版は年分で選ぶ（`INCOME_XTX_VERSIONS`）：令和7年分は 25.0.1（様式は申告書 KOA020 23.0・決算書 KOA210 11.0・収支内訳書 KOA110 12.0）。表に無い新しい年分は、いちばん新しい版で書き出して知らせます（令和8年分は、国税庁が版を出したら表に足す）。書き出したものは、テストで国税庁の XSD に照らしています
  - 数字は画面の申告書・決算書の数字そのもの。第一表の事業（営業等）の区分は、優良な電子帳簿で届出書を出していれば 1、それ以外は 2（会計ソフトで記帳）。1 のときに遅れて登録が半分以上の年は、書き出すときに注意を出します。青色申告の印は青色の年だけ。配偶者特別控除は区分1 に 1、ひとり親控除・セルフメディケーション税制は区分に 1、特定親族特別控除は人数も書きます。提出年月日は書かない（e-Tax の側で入る）
  - 個人番号は書き出すときに入れてもらいます（本人・第二表に書く配偶者・親族・事業専従者。保存しない）。公金受取口座で還付を受けるときは本人の分が必須
  - 様式の行数より多い明細は、金額の大きい順に入れ、残りは「その他」の1行にまとめます（所得の内訳・事業専従者・減価償却は次葉合計の欄に。売上先・仕入先は上記以外の計に）。第二表の親族（4人）・事業専従者（2人）より多い人は書かず、書き出すときに知らせます
  - 第二表の事業専従者の欄：青色は決算書の「専従者給与の内訳」の書き込み（続柄・従事月数）から。生年月日と個人番号は、所得税の入力の配偶者・扶養親族のうち「専従者」に印を付けた同じ氏名の人から。白色は所得税の入力の事業専従者から、従事月数・程度・仕事の内容と事業専従者控除額を書く（「程度・仕事の内容」は白色申告者だけが書く欄。令和7年分 確定申告の手引き）
  - 給与があるときは、保険料の「うち年末調整等以外」の欄を書きません（源泉徴収票に載っていない分だけを書く欄のため）。給与が無ければ全額を書きます
  - 第四表：(67)・損益の通算の各欄・(81) は経常所得の額、(82)、「4 繰越損失を差し引く計算」の年分（A・B・C と「青色の場合」の年）と Ⓐ・Ⓑ・Ⓒ、(93)。第一表の ⑫・㉛ は書かず、㉜ は 0。繰越損失を使い切る年は第一表の (62) に書きます
  - 書き出せないもの：令和6年分以前。源泉徴収された収入は、支払者の名称と法人番号又は所在地が要ります
  - 書かない欄：売上先・仕入先の法人番号、軽減税率対象の売上・仕入（収支内訳書。省略できる欄）、地代家賃の権利金・更新料、第二表の国外居住親族・別居の親族の住所、住宅借入金等特別控除の区分
  - 医療費控除・セルフメディケーション税制の明細書は、明細を入れたときだけ書き出します（KOB560・KOB570）。合計だけで申告するときは、e-Tax で出しても明細書を書面で別に出す決まりで（確定申告書等作成コーナーの「医療費の合計額のみを入力」と同じ扱い）、書き出すときにそう知らせます。明細書の次葉（17行目・19行目から）には対応していないので、行が多すぎれば書き出せません。ほかの様式の対応は `spec/etax/coverage.md`

## 銀行・カードの明細の取り込み
- 帳簿入力の画面の「明細の取り込み」から。取り込む先の口座（科目・補助科目）は、開いている帳簿のもの。銀行なら普通預金など、カードなら未払金（カードごとに補助科目）にします（計算は `lib/bankImport.ts`）
- **CSV を読む**：銀行・カードのサイトから書き出した CSV（UTF-8・Shift_JIS）。列（日付・摘要・入金と出金、または金額1列・残高）は見出しの名前から推測し、違えば選び直せます。選んだ対応は口座ごとに覚えます（`bank_formats`）
  - 見出しの例：お預け入れ・お引出し、預かり金額・支払い金額、入出金（1列で＋が入金）、カードの利用金額（「○月支払金額」の列より先に使う）。残高の列があれば、前の行の残高 ± 金額 ＝ その行の残高 になるかを照らし、入金と出金を逆に読んでいそうなら知らせます
  - 「増える側・減る側」で読みます：普通預金なら入金で借方、未払金ならご利用で貸方（カードは利用日に「経費／未払金」、引き落としは銀行の明細で「未払金／普通預金」）
  - 日付は 2026/1/5・2026-01-05・2026年1月5日・20260105・R8.1.5・26/01/05 など、金額は 3,300・¥3,300・-3,300・▲3,300・(3,300) など。日付の無い行（合計など）・金額が 0 の行は飛ばします
  - 読んだ明細は「未登録の明細」に入れます（`bank_lines`）。日付・増減・金額・摘要が同じ明細（同じ組み合わせが何個目かまで）は、もう一度読んでも入れません
- **未登録の明細**：行ごとに相手科目・税区分・仕訳の摘要・取引先を決め、チェックした明細をまとめて仕訳にします（1つのトランザクション）。仕訳はこの口座と相手科目の2行で、税区分は相手科目の側。家事按分（入力のたびに分ける科目）は事業分と事業主貸に分けます
  - **相手科目を分ける**：行の「分ける」で、相手科目を何行かにできます（例：ローンの返済を借入金と利子割引料に、カードの1回の利用を消耗品費と事業主貸に）。分けた行は入れた額、最初の相手科目は明細の金額の残り。分けた行の合計が明細の金額以上なら登録できません。分けた行ごとに税区分・摘要（空なら最初の行と同じ）を選べます
  - 推測：ルール（摘要に含む言葉。入金・出金・口座を絞れる。上から順に最初に合ったもの）→ 同じ口座で前に同じ摘要だった仕訳（明細から作った仕訳は、もとの明細の摘要でも引ける）。行から「ルールを作る」、「ルールを当て直す」もできます（`bank_rules`）
  - ルールにも分け方を持たせられます（決まった額を別の相手科目に。例：「ローン」なら利子割引料 6,000円、残りは借入金。`bank_rule_splits`）。行から「ルールを作る」と、その行の分け方も写します。前の仕訳からの推測では分けません
  - 帳簿に同じ日・同じ増減・同じ金額の仕訳がある明細は「重複かも」とし、初めはチェックを外します。取り込まない明細は「取り込まない」にでき（次に読んでも出さない）、未登録に戻せます
  - CSV に残高があれば、いちばん新しい明細の残高と、その日の帳簿の残高を比べて知らせます
  - 登録した回ごとに「取り込みの記録」（`import_batches`）に残し、仕訳日記帳の「取り込みの記録」からその回の仕訳をまとめて削除できます（明細は未登録に戻る）
  - 仕訳を削除すると、その明細は未登録に戻ります。厳密モードでは、仕訳の登録の履歴に「明細の取り込み（ファイル名）」と残ります。明細・ルール・列の対応は帳簿そのものではないので履歴には残しません

## 仕訳の CSV 取り込み
- 仕訳日記帳の「CSV 取り込み」から。形式は **仕訳日記帳の CSV 書き出しと同じ**（書き出したものをそのまま取り込める）。文字コードは UTF-8 / Shift_JIS
- 列は見出しの名前で探します（順番は問わない）。必須は 日付・借方科目・借方金額・貸方科目・貸方金額。任意で 伝票No・借方補助・貸方補助・摘要・取引先・状態・決算整理・借方税区分・借方インボイス・貸方税区分・貸方インボイス
  （税区分・インボイスが空なら、科目・取引先の初期値。免税事業者の期間の仕訳では外れる）
  - ほかの会計ソフトの見出し（取引日・借方勘定科目・借方補助科目・借方金額(円)・伝票番号 など）も読みます。見出しで分からなければ、**画面で列を選べます**（「列の対応」。必須の列が見つからないときは開いて知らせる）
- 同じ伝票No の行は1つの仕訳（複合仕訳）になります。伝票No が無ければ1行で1つ。状態が「削除済み」の行は飛ばします
- 日付は年つき（2026-01-05、2026/1/5、2026年1月5日、20260105）か和暦（R8.1.5・R08/01/05・令和8年1月5日・令和元年5月1日・H31.4.30 など。令和・平成・昭和）
- **二重の確かめ**：帳簿に同じ日・同じ明細（科目・補助科目・貸借・金額の組み合わせ）の仕訳があるもの、ファイルの中で前の行と同じものには印を付け、初めは取り込まない側にします（チェックを入れれば取り込める）。同じファイルを2回取り込んでも2倍になりません
- 科目・補助科目・取引先は名前で探します（全角半角・空白の違いは無視）。一覧に無い名前は自動で作らず、問題として知らせます
- 取り込む前に中身を確かめて一覧で見せます。1か所でも問題があれば、行番号つきで知らせて1件も取り込みません。取り込みは1つのトランザクションなので、途中で失敗しても1件も残りません
- 厳密モードでは、登録の履歴に「CSV 取り込み（ファイル名）」と残ります。登録日時は取り込んだ日時なので、過去の仕訳は「遅れて登録」と表示されます
- 取り込んだ回ごとに「取り込みの記録」（`import_batches`・`import_batch_entries`。日時・ファイル名・操作した人・登録した数と残っている数）を残します。
  同じファイルを2回取り込んだときなどは、仕訳日記帳の「取り込みの記録」から、その回の仕訳をまとめて削除できます

## 仕訳のまとめての削除
- 仕訳日記帳で行のチェックを付けて選び（見出しのチェックで表示中のものをすべて）、「選んだ仕訳を削除」で、理由を1つ入れてまとめて削除します（`deleteEntries`）。
  削除済みの仕訳と、締めた月の仕訳は選べません
- 1つのトランザクションなので、締めた月の仕訳が混ざっていたら1件も削除しません。厳密モードでは理由が必須で、1件ずつ「削除」として履歴に残ります（通常モードは本当に消します）
- 取り込みの記録からは、その回で登録した仕訳のうち残っているものをまとめて削除します（`deleteImportBatch`）

## 帳簿をまとめて書き出す
- 事業者設定の「帳簿をまとめて書き出す」で、年（何年分でも）を選び、選んだフォルダの中に `帳簿_名前_年_日付` のフォルダを作って書き出します（税務調査での電子データの提出（ダウンロードの求め）、ほかのソフトへの乗り換え、控え）
  - 年ごとに、仕訳日記帳・総勘定元帳・残高試算表（1月〜決算整理。補助科目つき）・固定資産台帳（償却する資産があれば）の CSV。各帳簿の画面の CSV と同じ形です（作り方は `lib/bookExport.ts` で共通）。科目・補助科目はその年の名前
  - 厳密モードでは、訂正削除履歴・変更履歴（科目・期首残高・締めなど）・証憑の履歴の CSV（選んだ年の分）
  - 取引年月日が選んだ年の証憑のファイルと証憑一覧.csv（「証憑」のフォルダ）
  - 何を書き出したかの「書き出しの内容.txt」

## 期首残高・科目・取引先の一覧の CSV
- ほかの会計ソフトからの乗り換えや、帳簿の間での写しに使います（`lib/masterCsv.ts`）。書き出したものをそのまま取り込め、列は見出しの名前で探します（順番は問わない。UTF-8・Shift_JIS）
- **期首残高**（期首残高の画面）：区分・科目・補助科目・金額。科目・補助科目は名前で探し、無いもの・損益の科目は問題として知らせます（先に一覧を取り込む）。同じ科目・補助科目の行は足します。▲・△ はマイナス。取り込むと画面の値を置き換え、「保存」で確定します（差額は今までどおり元入金で調整）
- **勘定科目・補助科目**（勘定科目の画面）：科目は コード・科目・よみ・区分、補助科目は 科目・補助科目・よみ。**無い名前のものだけ足します**（ある名前は飛ばす。名前を変えたり消したりはしない）。区分は 資産・負債・資本・収益・売上原価・経費・専従者給与等 のほか、流動資産・販売費及び一般管理費 などの言い換えも読みます。コードはその区分の範囲で空いていれば使い、無ければ空いている番号
- **取引先**（取引先の画面）：取引先・よみ・登録番号・適格請求書発行事業者ではない（○）・メモ。無い名前だけ足します
- 1か所でも問題があれば、行番号つきで知らせて1件も取り込みません

## 帳簿の印刷・CSV
電子帳簿保存法施行規則2条2項2号は、帳簿を「画面と書面に、整然とした形式・明瞭な状態で、速やかに出力できること」を求めます（優良な電子帳簿でも一般の電子帳簿でも同じ）。そのため、帳簿の画面ごとに「印刷」を付けています。

| 画面 | 印刷するもの | CSV |
|---|---|---|
| 仕訳日記帳 | 表示中の仕訳（期間・絞り込みの条件をページの見出しに。期間が12月までなら「決算整理前」と添える） | 既存 |
| 総勘定元帳 | この科目（選んでいる補助科目）か、すべての科目。補助科目ごとに分けると補助元帳 | すべての科目（表示中の期間） |
| 帳簿入力 | 表示中の帳簿・補助科目・期間を出納帳の形で（現金出納帳・預金出納帳・売掛帳・買掛帳など） | 総勘定元帳の CSV で代える |
| 残高試算表 | 貸借対照表と損益計算書（表示中の期間・条件）。月次推移表は A4 横、前年比較は前年の同じ期間と並べる | 両方を1つのファイルに（月次推移表は表示中の方。損益と貸借で列が違うため） |
| 固定資産台帳 | その年に償却する資産（絞り込みの条件つき） | 同じ |
| 訂正・削除履歴 | 表示中のタブ（仕訳は訂正前と訂正後を並べる） | 既存 |

- 「印刷」で印刷プレビューを開き、そこから印刷します（macOS の印刷ダイアログ。「PDF として保存」もここから）。用紙は **A4 縦**、列の多い月次推移表だけ **A4 横**（ほかの用紙では崩れます）
- ページは domble が分けます（`lib/printLayout.ts`）。行の高さは、ページと同じ幅の見えない表で測ってから分けます（摘要の折り返しで高さが変わるため。`components/PrintPreview.tsx`）
  - 各ページに、帳簿の名前・屋号と氏名・期間・科目・ページ番号（3 / 12 ページ）・出力日と、表の見出し
  - 1つの仕訳（複合仕訳の複数行）、月計と累計、試算表の区分（見出し・科目・小計）、履歴の1件（訂正前と訂正後）は、ページをまたがせない（一問一答の問11：1つの記録が複数枚に分かれる出力は「整然とした形式」に当たらない）。1ページに入りきらないときだけ行で分けます
  - 総勘定元帳・補助元帳は科目ごと、試算表は貸借対照表・損益計算書ごとに改ページ。元帳の続きのページは「前頁より繰越」から
  - 元帳の月計・累計：月の終わりに、その月の借方・貸方の合計と、年の初めからの累計。決算整理仕訳は12月のあとの「決算整理」の期間として別に合計
- 中身は `lib/printBooks.ts`（純粋関数・テストあり）。決算書・申告書の印刷は今までどおり画面をそのまま印刷します

## 操作説明書・システム概要書
電子帳簿保存法施行規則2条2項1号のシステム関係書類のうち、操作説明書とシステム概要書を `docs/manual` に Markdown で置いています（事務処理マニュアルは「電子帳簿保存法」の画面のひな形を、自分の運用に合わせて直してもらう）。
- アプリに取り込んで（Vite の `?raw`）、「操作説明書」の画面で読む・印刷します。アプリの版と一緒に管理するので、その版の画面にそった内容になります。印刷すると版と出力日が入ります
- 書き方は、説明書で使う分だけの Markdown（見出し・段落・箇条書き・表・太字・コード。`lib/markdown.ts`）。段落の中の改行は改行のまま出します
- 操作説明書：全体の流れ、帳簿を作る・開く、日々の入力、訂正・削除、検索、帳簿の出力、訂正・削除履歴と改ざんの確認、締め、決算、申告、翌年へ、バックアップ、ユーザーと暗号化、画面の一覧
- システム概要書：帳簿ファイルとデータの構成、保存方式、訂正・削除の履歴、改ざんの検知、入力期間、検索、出力、帳簿間の関連、締め、ユーザーと権限、暗号化、保存とバックアップ、証憑

## 消費税
制度は令和8年分に合わせています（計算は `lib/tax.ts`、集計と確認は `lib/taxSummary.ts`、申告書の数字は `lib/taxReturn.ts`、選択肢と科目の初期値は `constants/tax.ts`）。明細に税区分を持たせて集計・確認し、申告書に書き写す数字まで出します（税込経理・割戻し計算）。
- **年度ごとの設定**（`tax_years`。その年から、次に設定を変える年まで引き継ぐ）：課税区分（免税・本則・簡易・2割特例・3割特例）、経理方式（税込経理・税抜経理）、簡易課税の主な事業区分、本則課税の控除の方式（課税売上割合が 95% 未満のときの個別対応方式・一括比例配分方式）、年の途中から課税事業者になった日、任意の中間申告の届出
  - 一括比例配分方式は2年続けて使う決まりのため、一括比例配分方式にした翌年は個別対応方式を選べません
  - 2割特例は令和8年（2026年）分まで、3割特例は令和9年分・令和10年分だけ選べます。前の年から引き継いだ課税区分がその年に使えなければ知らせます
  - 年の締めをした年度の設定は変えられません（トリガーでも拒否）。変更は履歴に残ります（厳密モード）
- **本則課税の用途区分**（課税対応・共通対応・非課税対応。個別対応方式で使う）は課税仕入の明細ごと（`journal_lines.purchase_use`）。本則課税の年は帳簿入力・振替伝票の税区分の欄で選べます
  - 登録するときに、明細で選んだ区分 → 科目の初期値（勘定科目の画面の「用途区分」）→ 共通対応 の順で決めて記録します。CSV 取り込みでは共通対応は入れません（用途区分の列が無ければ分からないまま）
  - 区分の無い課税仕入は共通対応として計算し、個別対応方式を使うとき（課税売上割合が 95% 未満）は「確認」で知らせます。事業者設定の「科目の初期値で入れる」でまとめて入れられます
  - 用途区分も訂正の履歴・改ざんの確認・CSV（借方用途区分・貸方用途区分）・家事按分の年末の振替に入ります。仕訳の表示では課税対応・非課税対応だけ出します（共通対応は出さない）
- **適格請求書発行事業者の登録番号と登録日**は帳簿に1つ（事業者設定の「消費税」）。免税事業者のままで登録番号があれば知らせます
- **税抜経理**（経理方式を税抜経理にした課税事業者の年。`lib/taxExclusive.ts`）
  - 仕訳は今までどおり税込の金額で入れ、明細ごとに消費税額を持ちます。自動（税込の金額 × 10/110・8/108、1円未満切り捨て。経過措置の仕入れは控除できる割合、控除しない仕入れは 0、輸入の消費税は金額そのもの）で、振替伝票で直せます（直した額だけ `journal_lines.tax_amount` に保存。履歴・改ざんの確認にも入る）
  - 帳簿（総勘定元帳・残高試算表・帳簿入力）と決算書は、明細を本体（税抜）と仮受消費税等（売上・貸倒れの側）・仮払消費税等（仕入の側）に分けて出します。仕訳日記帳は入れたとおり（税込）で、税区分に消費税額を添えます
  - 消費税の申告書・集計表は、今までどおり税込の金額から割戻しで計算します（明細の消費税額は使わない）
  - 年末に、決算整理の画面で、仮受・仮払消費税等の残高を消し、申告書の ㉖ を未払消費税等（還付なら未収入金）に、差額を雑収入（または雑費）にする精算の仕訳を作ります。中間納付は「仮払消費税等 ／ 普通預金」で入れておきます
  - 仮払消費税等（118）・仮受消費税等（261）は初めは非表示の初期科目で、税抜経理にすると表示します。免税事業者の年は税込経理だけ
  - 固定資産：税抜経理の年に取得した資産は、台帳の取得価額を税抜で入れます（少額減価償却資産などの判定も税抜）。売却の仕訳は税抜の売却額と帳簿価額の差を事業主借・事業主貸にします
  - 経理方式は年ごとなので、年の途中に切り替えても今までの仕訳は書き換えません（消費税額は自動で計算し直す）
- **基準期間（前々年）・特定期間（前年1〜6月）の課税売上高**（`lib/baseSales.ts`。事業者設定の「消費税」に内訳）
  - 課税売上（税抜き）－ 売上の返還（税抜き）＋ 輸出などの免税売上。基準期間に免税事業者だった期間の売上は税抜きしません（年の途中から課税事業者になった年は、その日の前後で分ける。国税庁の手引きの計算例どおり）
  - 税区分の無い明細（免税事業者の期間など）は、科目の税区分の初期値で売上かどうかを決めます。特定期間は給与等支払額（給料賃金・専従者給与）も出します
  - 基準期間の帳簿が domble に無いとき（または帳簿の計算と違うとき）は手で入れます（`tax_base_sales`。入れた額が優先。変更は履歴に残る）
  - 使い道：申告書の第一表（簡易課税用は ⑯、一般用は参考事項）、確認の一覧（1,000万円超なのに免税事業者・2割特例・3割特例、5,000万円超なのに簡易課税、分からないとき）、方式の比較（使えない方式は理由を出して比べない）
- **税区分は明細ごと**（`journal_lines.tax_code`）：対象外／課税売上 10%・8%（軽減）／輸出免税／非課税売上／課税仕入 10%・8%（軽減）／非課税仕入／貸倒れ 10%・8%（軽減）／輸入の消費税（国税 7.8%・6.24%。税関に払った消費税のうち国税の額そのものを金額に入れる。付表2-3 ⑮。地方消費税は対象外で入れる）／特定課税仕入れ（国外事業者からの広告配信などのリバースチャージ。支払った額を入れ、課税売上割合が 95% 未満の本則課税の年だけ課税標準額と ⑬⑭ に入れる。95% 以上・簡易課税・2割特例では無かったもの）
  - 値引き・返品は区分を増やさず、貸借の側で判定します（売上の区分が借方なら売上の返還、仕入の区分が貸方なら仕入の返還、貸倒れの区分は借方が貸倒れ・貸方が回収）
  - 初期値は科目から（勘定科目の画面で科目ごとに変えられる）。資産の科目の初期値は借方（取得）だけに使い、貸方（売却・償却）は対象外
  - 免税事業者の期間（課税事業者になった日より前も）の明細は税区分を持ちません（NULL）。画面では「対象外」で固定
- **インボイス区分は課税仕入の明細ごと**（`journal_lines.invoice_kind`）：適格／経過措置／控除しない／帳簿のみ保存の特例（3万円未満の公共交通機関の運賃・3万円未満の自動販売機・郵便切手で払う郵便・出張旅費等と通勤手当・回収される入場券等・登録していない者からの古物等。本則課税の年だけ選べる。控除は適格と同じで、帳簿・印刷・CSV に「帳簿のみ交通」などの特例の旨を出す）
  - 初期値は取引先から。「適格請求書発行事業者ではない」にした取引先なら経過措置、それ以外（取引先なしを含む）は適格
  - 経過措置で控除できる割合は課税仕入の日で決まり、帳簿に「経過80%」「（70%控除対象）」のように出します（令和8年9月30日まで 80%、10月1日から 70%、令和10年10月から 50%、令和12年10月から 30%）
- **簡易課税の事業区分は課税売上の明細ごと**（`journal_lines.business_class`。第一種〜第六種）
  - **登録するときに区分を決めて明細に記録**します：明細で選んだ区分 → 科目の初期値（勘定科目の画面の「事業区分（簡易課税）」。`accounts.default_business_class`）→ 年度の「主な事業区分」。業務用の固定資産の売却（資産の科目の課税売上）は第四種。あとで「主な事業区分」を変えても、登録済みの売上は変わりません
  - 簡易課税の年だけ、税区分の欄で「課売10% 2種」のように選べます。履歴の写し・照合・CSV（「借方事業区分」「貸方事業区分」）にも入ります。集計表は簡易課税の年の売上を事業区分ごとに分けます
  - **区分の無い売上は「不明」**：本則課税から簡易課税に変える前に入れた売上や、CSV 取り込みで区分を指定しなかった売上（取り込みでは「主な事業区分」は入れない。科目の初期値は入る）。帳簿に「課売10% 区分不明」と出し、「確認」で直すもの（赤）として知らせます。事業者設定の「科目の初期値で入れる」で、科目の初期値 → 主な事業区分 の順にまとめて入れられます
  - 不明のまま申告書の数字を出すときは、その年の売上に出てくる区分のうちみなし仕入率がいちばん低い区分として計算します（2種類以上の事業で区分していない売上の扱い。施行令57条④）。区分の分かる売上が1つも無ければ「主な事業区分」
- 入力：帳簿入力は相手科目の税区分、振替伝票は借方・貸方それぞれ。課税仕入はインボイス区分も同じ欄で選びます。科目を選ぶと初期値が入り（薄い字）、Enter での移動では飛ばします（変えるときはクリックか Tab）。科目を変えると初期値に戻ります
- 保存のときに、入っていない税区分を科目の初期値で、インボイス区分を取引先の初期値で埋めます（`repo.ts` の `withTax`。CSV 取り込み・家事按分・減価償却の仕訳も同じ）。家事按分で分けた家事分（事業主貸）は対象外
- 免税事業者から課税事業者に変えた年は、税区分の入っていない仕訳を「科目の初期値で入れる」でまとめて埋められます（1件ずつ訂正として保存。厳密モードでは訂正の履歴が残る。締めた月の仕訳は変えない）
- 表示：帳簿入力の税区分の列（入っていなければ「未設定」）、仕訳日記帳（対象外以外）、訂正・削除履歴の写し。仕訳日記帳の CSV に「借方税区分」「借方インボイス」「貸方税区分」「貸方インボイス」
- 厳密モード：履歴の写しと「今の中身との照合」に税区分・インボイス区分が入ります（税区分の無い仕訳の記録は今までと同じハッシュ）
- **「消費税」の画面**（集計の中）
  - **集計表**：課税事業者の期間の、削除済みでない明細を「区分（売上・売上の返還・貸倒れ・仕入・仕入の返還・対象外）× 税区分 × インボイス区分」で合計します。経過措置は控除できる割合（80%・70%）ごとに分けます。行を開くと科目ごとの内訳。対象外は損益の科目だけ（現金・預金などの相手側は出さない）。CSV に書き出せます
  - 消費税等の額は参考（税込の金額 × 税率 /（100 + 税率）の 1 円未満切り捨て）。申告の計算は端数の扱いが違います
  - **課税売上割合**（税抜・返還を差し引いた額。表示は小数第2位まで切り捨て）
  - **確認**：申告の前に直すもの（赤）・確かめるもの（黄）・念のため（青）。関係する仕訳はその場で開いて直せます
    - 課税区分がその年に使えない（引き継いだ2割特例が 2027年に入った、など。画面上部でも知らせる）、登録番号があるのに免税事業者
    - 方式の前提：2割特例・3割特例なのに登録番号・登録日（その年の12月31日以前）が無い、前の年が免税で年の途中に登録したのに「課税事業者になった日」が空（念のため）、簡易課税を1年で本則課税に戻した（2年継続）、簡易課税を始める年・やめる年の届出の念押し（前の年の課税区分が帳簿にあるときだけ）、本則課税の年に税抜 1,000万円以上の固定資産（高額特定資産）を取得したのに、その年から3年の間に免税事業者・簡易課税・2割特例・3割特例にした
    - 本則課税の年の、取引先も補助科目も無い課税仕入（帳簿に相手方の氏名又は名称が要る。摘要に書いてあればそのままでよい。念のため）
    - 税区分が入っていない仕訳
    - 科目と税区分の組み合わせ（収益に仕入、経費に売上、負債・資本・専従者給与に対象外以外）。資産の売却で資産に売上の区分は正しいので出さない
    - 「適格請求書発行事業者ではない」取引先からの「適格」、登録番号のある取引先からの「経過措置」、登録番号が入っていない取引先からの「適格」
    - 本則課税で課税売上割合が 95% 未満（控除の方式を確かめる）。個別対応方式なら用途区分の入っていない課税仕入。一括比例配分方式にした翌年に個別対応方式になっている
    - 売却した固定資産（台帳の売却日・区分）があるのに、その資産の科目に課税売上が無い。本則課税で家事と兼用する資産を取得した科目の課税仕入が、取得価額 × 事業専用割合 を超えている
    - 念のため：雑収入の課税売上（預金利息・補助金・保険金・還付金）、本則課税の地代家賃・福利厚生費の課税仕入（地代・住宅の家賃・社会保険料）、給料賃金に課税仕入が無い（通勤手当）
    - 中間申告が要るのに中間納付税額が 0、中間納付税額が前年の実績で計算した額と違う（仮決算なら構わない）、前年の確定消費税額が分からない
    - 課税売上割合が 95% 未満のとき、集計表の課税仕入は用途区分ごとに分けて出します
  - **申告書**：その年に使える方式（本則課税・簡易課税、令和8年分までは2割特例、令和9・10年分は3割特例）の納付税額を並べ、選んだ方式の付表・第二表・第一表を欄の番号つきで出します。確定申告書等作成コーナーや e-Tax に書き写すための数字です。e-Tax 用のデータ（.xtx）にも書き出せます（送信は e-Tax で行う）
    - 様式は令和5年10月1日以後終了課税期間用（標準税率・軽減税率だけの場合）：本則課税は付表1-3・2-3、簡易課税は付表4-3・5-3、2割特例は付表6、3割特例は付表6（小規模個人事業者用。⑥ × 70%）
    - 端数は国税庁の書き方どおり（途中の 1 円未満はその都度切り捨て、課税標準額は千円未満、差引税額・譲渡割額は百円未満を切り捨て）。国税庁の「申告書の書き方」「2割特例用の手引き」の設例と同じ数字になることをテストで確かめています（`lib/taxReturn.test.ts`）
    - 本則課税：付表2-3 の ③ 非課税資産の輸出等の金額は申告書タブで書き込みます（`tax_return_inputs`）。輸入の消費税は ⑮、特定課税仕入れは課税売上割合が 95% 未満のときだけ ⑬⑭（付表1-3 ①-2・第二表 ⑨⑩ にも）。インボイスのある仕入れは ⑨⑩、経過措置の仕入れは ⑪⑫（控除できる割合ごとに計算して合計。令和8年分は 80% と 70%）、控除しない仕入れは入れない。課税売上割合が 95% 未満（または課税売上高が5億円超）なら、年度の控除の方式で個別対応方式（⑲ 課税対応 ＋ ⑳ 共通対応 × 課税売上割合 ＝ ㉑。非課税対応は控除しない）か一括比例配分方式（㉒）。申告書タブには両方の額を並べ、有利なほうを知らせます
    - **棚卸資産の調整**（付表2-3 ⑯。消費税法36条・国税庁 No.6491）：本則課税の年に、申告書タブの「棚卸資産の調整」で税率（10%・8%）・控除できる割合（全額・経過措置の 80%〜30%）ごとの取得価額（税込）を入れます（年度ごと。`tax_inventory_adjusts`）。加算（免税事業者から課税事業者になった年：前日に持っていた棚卸資産のうち免税の期間に仕入れたもの）と減算（翌年から免税事業者になる年：年末に持っている棚卸資産のうちその年に仕入れたもの）を選び、初めは事業者設定の年度ごとの課税区分から選んでおきます。税額は取得価額 × 7.8/110・6.24/108（経過措置は割合を掛ける）で、⑰ に加え、個別対応方式では課税対応（⑲）に入れます。「帳簿の期首（期末）の棚卸高から入れる」で、期首商品棚卸高（期末商品棚卸高。無ければ棚卸資産の残高）を 10%・全額の1行として入れられます。国税庁の設例（甲野商店）の ⑰・第一表 ⑨・地方消費税と同じになることをテストで確かめています。棚卸資産の明細（品名・数量・取得価額）は棚卸表で別に記録・保存します
      - 確認の一覧：前年が免税で本則課税になった年に期首の棚卸高があるのに加算が無い・年の途中から課税事業者になった・翌年から免税になる年に年末の棚卸高があるのに減算が無い・本則課税でないのに調整が入っている、を知らせます
    - 簡易課税：事業区分が1種類なら付表5-3 の ⑤。2種類以上なら ⑥〜⑲（区分ごとの売上・売上割合・税額）から、⑳ 原則計算・㉑ 1種類で75%以上・㉒〜㊱ 2種類で75%以上 を計算し、控除対象仕入税額がいちばん多いものを ㊲ に選ぶ（税率ごとに違う計算は選ばない）。第一表の参考事項に区分ごとの課税売上高（千円未満四捨五入）・売上割合・特例計算（令57③）の有無。国税庁の書き方の設例（第二種と第四種）と同じ数字になることをテストで確かめています
    - 2割特例・3割特例の第一表は、簡易課税の届出の有無で一般用か簡易課税用を選べます（欄の番号は同じで、③ の名前だけ違う）
    - 中間納付税額（消費税・地方消費税）は年度ごとに入れます（`tax_interims`。変更は履歴に残る。年の締めをした年度は変えられない）。「判定した額を入れる」で、中間申告タブの合計を入れられます
    - 方式の比較は表示だけで、課税区分は事業者設定で決めます。「印刷」で付表・第二表・第一表を印刷できます
  - **中間申告**：前年の確定消費税額（第一表の ⑨ 差引税額。地方消費税は含まない）から、その年の中間申告の回数・対象期間・期限・額を出します（`lib/taxInterim.ts`）
    - 48万円以下は要らない（任意の中間申告の届出をしていれば年1回）、400万円以下は年1回（6/12）、4,800万円以下は年3回（3/12）、超えたら年11回（1/12）。1回の額は百円未満切り捨て、地方消費税はその 22/78（百円未満切り捨て）
    - 期限は対象期間の末日の翌日から2か月以内（年11回の1月分・2月分は5月31日）。土日・祝日・12月29日〜1月3日なら次の日（祝日は「祝日・休業日」の一覧。事業者の休業日はずらさない）
    - 前年の ⑨ は、前年の帳簿を前年の課税区分（事業区分・控除の方式も前年のもの）で計算します。前年の帳簿が無いとき・修正申告で変わったときは手で入れます（`tax_prev_amounts`。変更は履歴に残る）
    - 個人事業者の課税期間は暦年なので、前年の途中から課税事業者になっていても月数で割りません。仮決算による中間申告・中間申告書の e-Tax 用のデータ・課税期間の短縮の特例は扱いません
  - **還付申告に関する明細書**：一般用で ⑧ 控除不足還付税額があると、申告書の数字の下に「消費税の還付申告に関する明細書（個人事業者用）」を出します（計算は `lib/taxRefundDetail.ts`。書き方は国税庁の記載要領に沿う）。年ごとに保存し、印刷・e-Tax 用のデータに入れられます

    - 2(1) 主な課税資産の譲渡等・3(2) 主な棚卸資産・原材料等の取得：税区分が課税売上・課税仕入の明細のうち、税抜 100万円以上を上位5件。同じ取引先との取引が続いていれば、その年の合計を「継続」の1件にする。3(2)・3(3) は取引先の登録番号も入れる
    - 2(2) 主な輸出取引等の明細：輸出免税の売上を取引先ごとに合計して上位5件。所轄税関・利用する金融機関・通関業者は入力

    - 3(3) 主な固定資産等の取得：固定資産の科目への課税仕入のうち、1件あたり税抜 100万円以上を上位5件
    - 明細の行は帳簿からの候補で、資産の種類・取引先の住所などは画面で直す（「帳簿から作り直す」で候補に戻せる）。金額は税込（税込経理）
  - **e-Tax 用のデータ（.xtx）**：選んだ方式の申告書（確定申告）を、e-Tax の XML 形式で書き出します（`lib/taxXtx.ts`・`lib/etax.ts`）。e-Taxソフト（WEB版）の「作成済みデータの利用」で読み込んで送信します（WEB版は読み込んだデータを直せないので、個人番号と還付先は書き出すときに入れておく）
    - 手続の版は年分で選ぶ（`XTX_VERSIONS`）：令和7年分・令和8年分は 23.2.0（令和8年9月30日以前に開始した課税期間用。国税庁が個人事業者の令和8年分にこちらを指定）、令和9年分は 26.0.0（令和8年10月1日以後開始の課税期間用。中の様式は同じ）。表に無い新しい年分は、いちばん新しい版で書き出して知らせます。第一表が一般用なら RSH0010（本則課税は第一表・第二表・付表1-3・2-3、2割特例は第一表・第二表・付表6）、簡易課税用なら RSH0030（簡易課税は付表4-3・5-3、2割特例は付表6）。3割特例は国税庁の様式がまだ無いため書き出せません。令和6年分以前の年分は対象外
    - 一般用で ⑧ 控除不足還付税額があるときは、**消費税の還付申告に関する明細書（個人事業者用）**（SHC025）も入れます（消費税法施行規則22条3項。保存するまでは書き出せない）
    - 数字は画面の申告書の数字そのもの。付記事項・積上げ計算の特例は「無」、控除税額の計算方法は個別対応方式（1）・一括比例配分方式（2）・全額控除（3）・2割特例（8）、簡易課税用の2割特例は「該当」にします。提出年月日は書かない（e-Tax の側で入る）
    - 個人番号は、書き出すときに入れてもらいます（検査用数字で打ち間違いを確かめる。domble には保存しない）。IT部に書き、第一表から参照します
    - 還付になるときだけ、事業者設定の還付される税金の受取場所を書きます：銀行等・ゆうちょ銀行の口座は IT部の還付先金融機関、公金受取口座は第一表の口座情報利用同意区分を「該当」（個人番号が必須のため、入れたときだけ）
    - 申告者の情報（利用者識別番号・提出先の税務署・電話番号・氏名と屋号のフリガナ・還付される税金の受取場所）は事業者設定の「e-Tax の申告者の情報」で入れます。所得税の確定申告書に書く職業・世帯主の氏名と続柄・事業所の電話番号、青色申告決算書に書く事業所の所在地・加入団体名、依頼している税理士等（氏名・事務所の所在地・電話番号）もここで入れます（1月1日の住所は年分ごとに所得税の入力で）。氏名・屋号・郵便番号・住所は「事業者の情報」のもの。税務署の一覧は国税庁の XSD から作っています
    - 国税庁の XSD（`spec/etax`。消費税の手続に要る分だけ）で、書き出したデータが形式に合っているかをテストで毎回確かめています（`lib/taxXtx.test.ts`。xmllint を使う）。XSD を差し替えたら `python3 -I scripts/etax_forms.py` で項目の並び（`lib/etaxForms.ts`）と税務署の一覧（`constants/taxOffices.ts`）を作り直します
- **家事按分の年末の振替**は、家事分をその科目の明細の税区分・インボイス区分ごとに、年間の計上額の割合で分けて戻します（端数は大きい余りから 1 円ずつ）。経過措置の仕入れが混ざっていても、仕入の返還が正しく出ます。税区分の無い明細（免税事業者の期間など）の分は対象外
- 仕訳日記帳は税区分で絞り込めます（未設定・経過措置・控除しない・税区分ごと）。総勘定元帳にもその科目側の税区分を出します

## 入力期間
- 優良な電子帳簿の「通常の期間を経過した後に入力した場合は、その事実を確認できること」に対応するもの
- 取引日から、事業者設定の **入力期間（日）** を過ぎて登録した仕訳を、仕訳日記帳で「遅れて登録」と表示します。
  「入力期間を過ぎて登録したもの」で絞り込め、CSV には登録日時・登録までの日数・入力期間を過ぎたかが出ます
- 既定は 70 日（業務処理サイクル方式の「最長2か月 + おおむね7営業日」の目安）。事務処理規程などで決めた期間に合わせます
- 登録日時は、厳密モードでは登録時の履歴（`entry_history` の create。記録の連鎖に入っている）から取ります。仕訳の `created_at` を直接書き換えても結果は変わりません
- 入力期間の変更は、厳密モードでは履歴に残ります（どの仕訳が「遅れて登録」に当たるかが変わるため）
- 訂正は対象外です（訂正の事実は訂正・削除履歴で確認できるため）。判定は「最初に登録した日」で行います
- **まとめて入力した年**：優良な電子帳簿は、年の初めに備え付けて順次記録していくことが前提です（一問一答〔帳簿〕問29）。年が終わってから作った帳簿は、初日から優良な電子帳簿で備え付けていたことにならず、優遇措置を受けられません（同 問42（注））。
  そこで「電子帳簿保存法」の画面に、その年の仕訳の数・遅れて登録の件数と割合・年が明けてから登録した件数（決算整理を除く）・CSV 取り込みで登録した件数・最初の登録日を出します。
  法令に割合の決まりは無いので、遅れて登録が **半分以上** の年は、状態の帯を「注意」にして、優遇措置を受けられないおそれを知らせます（`lib/ebook.ts` の `inputTimeliness`）。e-Tax の書き出しで第一表の区分を「優良な電子帳簿」にするときも、同じ注意を出します

## 証憑（電子取引データ）
- メールなどで受け取った請求書・領収書を、**受け取ったファイルのまま**（変換せずに）帳簿ファイルの中に保存します。1件 10MB まで
- 取り込める形式：PDF、画像（JPEG・PNG・HEIC/HEIF・GIF・WebP・TIFF）、Excel（xlsx・xls）、Word（docx・doc）、ZIP、XML、CSV、テキスト。
  種類は拡張子ではなく中身で判定し、何のファイルか判定できないもの（実行ファイルなど）は受け付けません（旧形式の Office と、CSV・テキストの区別だけは拡張子も見ます）
- 画面での表示は形式ごと：PDF・画像はそのまま、CSV・XML は文字として（UTF-8 で読めなければ Shift_JIS）、Excel・Word・ZIP は表示せず「書き出して開く」。
  変換が要るときも表示のときだけ行い、保存しているファイルとハッシュは変えません
- 証憑ごとに **取引年月日・取引金額・取引先**（電子取引データの検索要件の項目）を持ちます。仕訳がまだ無い証憑も登録でき、あとから仕訳とひも付けます
- 仕訳とのひも付けは多対多（請求書1枚を分割で支払う、1つの仕訳に請求書と領収書、など）。仕訳の訂正画面から「取り込んでひも付ける」「登録済みから選ぶ」ができます
- ファイルの中身は登録後に差し替えできません（トリガーで拒否）。差し替えるときは新しく登録し、古い方を無効にします
- **証憑の履歴は、帳簿の保存方式によらず残します**（電子取引データの保存は、すべての事業者の義務のため）。登録・訂正・無効・ひも付けを証憑ごとの履歴（`evidence_history`）に残し、詳しく見る画面に出します。無効には理由が必須です（訂正の理由は厳密モードで必須、通常モードで任意）。記録の連鎖に入れるのは厳密モードだけです
  - 通常モードでは、本当に削除することもできます。ファイル・ひも付け・履歴は消え、削除したこと（日時・理由・最後の内容・消した履歴の件数・操作した人）を `evidence_deletions` に残し、証憑の画面の「削除した証憑」に出します。厳密モードでは削除できません（トリガーでも拒否）
- **電子取引データの真実性**：domble はタイムスタンプを付けず、メールなどで受け取ったデータを取り込むのは「保存」だけなので、訂正・削除の履歴が残る仕組みで受け取ったことにもなりません（一問一答〔電子取引〕問43）。
  そのため、訂正及び削除の防止に関する事務処理規程（電子帳簿保存法施行規則4条1項4号）で満たしてもらいます。「電子帳簿保存法」の画面の「電子取引データの保存」で、要件・自分で行うことのチェック（年ごと）と、規程のひな形（国税庁のサンプル〔個人事業者の例〕に沿い、訂正・削除の手順を domble の訂正・無効に合わせたもの。`lib/ebook.ts` の `electronicRule`）を保存できます
- 登録時にファイルの **SHA-256** を記録します。「改ざんの確認」で、中身から計算し直したハッシュを、記録と登録時の履歴（厳密モード、書き換え不可）の両方と照らし合わせます
- 「ファイルを書き出す」で、検索結果のファイルを `取引年月日_取引先_金額_No.拡張子` の名前で一覧 CSV と一緒にフォルダへ書き出します（税務調査での「ダウンロードの求め」を想定）
- ファイルは base64 の文字列で SQLite に保存しています（画面との受け渡しが JSON のため。容量は約 1.33 倍）

## スキャナ保存（紙の証憑を読み取って保存）
令和6年1月1日以後の要件にそって確かめます。電子帳簿保存法に対応した保存方式（厳密モード）の帳簿だけで使えます（訂正・削除の履歴を残すことが要件のひとつのため）。
- **タイムスタンプは付けません。そのため domble だけでは、スキャナ保存の要件を満たしません。読み取って取り込んだ書類も、紙の原本を保存してもらいます**。
  登録日時は利用者の PC の時計なので、「入力期間内に保存したことを確認できる」こと（タイムスタンプに代える措置）にもなりません（一問一答〔スキャナ保存〕問21・31・32：保存日時を他者が客観的に担保する仕組みでなければ代えられない）。
  取り込みの画面・詳しく見る画面・一覧の印・事業者設定・事務処理マニュアルのひな形で知らせます（`lib/scan.ts` の `SCAN_KEEP_PAPER`）。下の入力期間・画質の確かめは参考として出します（認定タイムスタンプを足すときに要る）
- 取り込みの画面で区分を「スキャナ保存（紙を読み取ったもの）」にします。受領日（紙を受け取った日）が必須です
- **書類の区分**：重要書類（契約書・領収書・請求書・納品書など）／一般書類（見積書・注文書）。書類の種類から自動で選び、変えることもできます
- **入力期間**：事業者設定で方式を選びます（早期入力方式＝受け取ってからおおむね7営業日以内／業務処理サイクル方式＝事務処理規程で決めたサイクル〔1か月・2か月〕＋おおむね7営業日以内）。
  取り込みの画面に入力期限と残りの営業日を出します。期限を過ぎても登録はできますが「入力期間外」の印がつきます（要件を満たさないので紙の原本も保存）
- **画質**：JPEG・PNG はファイルの中身で確かめます（200dpi 以上と書かれているか、画素数が A4 の 200dpi 相当（長い辺 2,338・短い辺 1,654 画素）以上。写真の 72dpi などの表示は画像の解像度を表さないことが多いため、200dpi 未満なら画素数で判断。重要書類はカラー、一般書類はグレースケールも可）。
  足りなければ取り込めません。PDF・HEIC など中身を読めない形式は「200dpi 以上・カラーで読み取った」の確認（自己申告）で取り込みます。確認の結果は取り込んだときのまま残り、書き換えられません
- **事務処理規程**：業務処理サイクル方式は、各事務の処理に関する規程を定めている場合に限り使えます（電子帳簿保存法施行規則2条6項1号ロ）。事業者設定のスキャナ保存の欄で、業務処理サイクル方式を選ぶとそのことを知らせ、規程のひな形を保存できます。
  ひな形は国税庁のサンプル（スキャナによる電子化保存規程）の章立てに沿い、個人事業者が domble で取り込む形にしたもの。選んだ方式の入力の時期が入り、タイムスタンプが無いので原本は廃棄せずに保存する形です（`lib/ebook.ts` の `scanStorageRule`）
- **帳簿との相互関連性**：重要書類は仕訳とのひも付けが必要です。ひも付いていないものには「要ひも付け」の印がつきます
- 一覧・詳しく見る画面・CSV に、区分・入力期限・期間内か・画質が出ます。区分（電子取引・スキャナ保存）で絞り込めます

## 祝日・休業日
- 営業日は、土日・祝日・休業日を除いて数えます（スキャナ保存の入力期限など）
- **祝日**はソフトに内蔵しています（内閣府「国民の祝日」の CSV から作成。2000年〜2027年。`src/constants/holidays.ts`）。
  新しい年の分は、事業者設定の「最新の祝日を取得」で内閣府から取得できます（押したときだけ接続。取得先は Rust 側で決め打ち。取得できなくても内蔵の祝日で動く）。
  来年の祝日が無ければ画面で知らせます
- **休業日**（年末年始・お盆休みなど）は事業者設定で足せます。「年末年始（12/29〜1/3）を足す」ボタンもあります
- 取得した祝日と休業日は帳簿ファイルに保存し、変更は「訂正・削除履歴」に記録します（厳密モード）

## 取引先（任意）
- 補助科目とは別に、取引先の一覧を持ちます（同じ相手が売掛金にも外注工賃にも出てくるため）。適格請求書発行事業者の登録番号（T + 13桁）も持てます
- 仕訳1件に1つ付けられます（帳簿入力・振替伝票・仕訳の訂正画面）。1つの伝票に複数の相手が混ざる場合は、伝票を分けて入力します
- 一覧に無い名前は、入力欄の「取引先に追加」でその場で登録できます
- 証憑の取引先名が一覧の名前と同じなら、その取引先とつながります（CSV に登録番号も出ます）
- 仕訳日記帳で取引先による絞り込み、CSV に取引先・登録番号。履歴の写しには記録した時点の取引先名が残ります
- 使った取引先は削除できません（非表示にはできます）

## 改ざんの検知（厳密モード）
帳簿ファイルは普通の SQLite なので、ソフトを通さずに書き換えること自体は**防げません**（トリガーも消せます）。
また、ソースコードを公開しているため、ソフトの中に秘密の鍵を隠して守る方法も使えません。そこで「できるところまで検知する」方針にしています。

1. **記録の連鎖（ハッシュチェーン）**：履歴を1件書くたびに、1つ前の記録のハッシュを含めたハッシュを `audit_chain` に積みます。履歴を書き換え・削除すると、そこから先が合わなくなります
2. **今の中身との照合**：仕訳・証憑・期首残高・締め・固定資産台帳（年ごとの事業専用割合を含む）について、最後に記録した状態のハッシュと今の中身を比べます。履歴を残さずに直接書き換えたものが見つかります。
   固定資産台帳を照合に入れる前に連鎖を始めた帳簿は、その後に最初に開いたときの台帳を基準点にします
3. **トリガーの見張り**：前回開いたときにあったトリガーが消されていたら、記録して知らせます（トリガーは開くたびに作り直すため、黙って元に戻さないように）
4. **確認コード（外部の控え）**：連鎖をまるごと計算し直されると 1・2 では見抜けません。年度を締めたときの確認コード（連鎖の先頭のハッシュの一部）を、決算書の控えなど帳簿ファイルの外に残しておけば、あとで照らし合わせて見つけられます。
   確実にしたい場合は、書き出した確認コードのファイルに**有料のタイムスタンプ**を付けてください

帳簿を開くたびに軽い確認（1〜3）を行い（今の中身は仕訳・証憑・期首残高ごとにまとめて読むので、仕訳が増えても問い合わせの数は変わりません）、問題があれば画面上部で知らせます。「訂正・削除履歴」の「改ざんの確認」では、証憑ファイルの中身も含めて確かめ、確認コードの書き出し・照合ができます。
この仕組みを入れる前に作った帳簿は、最初に開いたときの状態を「基準点」として連鎖を始めます（それより前の改ざんは見つけられません）。

## ユーザー
- 帳簿を使う人を登録し、「誰が操作したか」を記録します
- 権限は3つ：**管理者**（すべて）・**入力担当**（仕訳・証憑・取引先・定型仕訳・CSV 取り込みなど日々の入力。設定・勘定科目・期首残高・ユーザーの管理は不可）・**閲覧のみ**（見るだけ）
  - 最初のユーザーと、権限を入れる前からいたユーザーは管理者。追加したユーザーの既定は入力担当
  - 権限を変えられるのは管理者だけ。使える管理者が1人もいなくなる変更はできない。自分のパスワードはどの権限でも変えられる
  - 権限は画面だけでなく、書き込みの入り口（repo.ts の tx）でも確かめる。権限の変更は履歴に残る（厳密モード）
- 帳簿を開くときに使う人を選びます。ユーザーが1人だけでパスワードもなければ、選ぶ画面は出ません（最初のユーザーは帳簿の持ち主の氏名で自動で作ります）
- パスワードは任意です（PBKDF2-SHA256 のハッシュで保存）。変更・解除には今のパスワードが要ります
- ログアウトは、「帳簿を閉じる」「ユーザーの切り替え」と、ウィンドウを閉じたとき（⌘Q を含む）に記録します。強制終了などで記録できなかったログインは、利用の記録に「ログアウトの記録なし」と出ます
- 操作者が残るところ：訂正・削除履歴（仕訳・科目など・証憑）、仕訳と証憑の登録者・最終更新者、利用の記録（ログイン・ログアウト）。厳密モードでは記録の連鎖にも入ります
- 履歴に名前が残るので、ユーザーは削除できません（非表示にはできます）

## 帳簿ファイルの暗号化（任意）
- 事業者設定の「帳簿ファイルの暗号化」で、帳簿ファイルにパスワードをかけられます（管理者のみ。8文字以上）。かけない使い方もそのままできます
- ファイル全体を SQLCipher の形式で暗号化します（ページごとに AES-256。改ざん検知の HMAC つき）。パスワードがないと中身を読めず、このソフトの外から書き換えることもできません
- 鍵はパスワードとファイルごとのソルトから Argon2id で作ります
- **回復キー**：暗号化したときに表示します（コピー・ファイルに保存できる）。パスワードを忘れても、開くときに「パスワードを忘れたとき（回復キーで開く）」から入れれば開けます。回復キーは鍵そのもので、パスワードを変えると新しくなります
- **この PC に記憶する**：開くとき・暗号化するときに選ぶと、鍵を OS の鍵の保管庫（macOS のキーチェーン、Windows の資格情報マネージャー）に預け、次からこの PC ではパスワードを聞かずに開きます。ファイルだけを持ち出したときは、ほかの PC ではパスワードを聞かれます。記憶は事業者設定で消せます
- パスワードの変更・暗号化をやめるには、今のパスワード（または回復キー）が要ります。かけた・変えた・やめたことは履歴に残ります（厳密モード）
- 暗号化した帳簿のバックアップ（.dmbk）も暗号化されたままです。パスワードを変えたあとも、それより前のバックアップは当時のパスワード（回復キー）で開きます（前の回復キーも残しておく）
- 暗号化する前に作ったバックアップは暗号化されていないので、件数を出して消せるようにしています（消す前に、暗号化したバックアップを今の中身で作る）
- かける・やめるときは、暗号化した（外した）写しを同じフォルダに作ってから置き換えます。途中で止まっても元のファイルは残ります
- 暗号化はパスワードを知らない人から守るものです。パスワードを知っている人による書き換えは、厳密モードの履歴と記録の連鎖で「わかる」ようにしています

## 保存とトランザクション
- 書き込みはすべてトランザクションの中で行います（`repo.ts` の `tx`）。途中で失敗したり、ソフトが強制終了したりしても、SQLite が書きかけを丸ごと取り消します
- 書き込みの前に「保存中」の目印（`pending_ops`）を置き、終わったら消します（トランザクションを始められなかったときも消す）。目印が残っていたら、次に開いたときに「前回、次の保存が完了しませんでした（取り消されています）」と知らせ、厳密モードでは検知の記録に残します

## 帳簿を作るとき（初期設定）
- 屋号（任意。無い人は空のまま。帳簿の表示名・ファイル名は屋号、無ければ氏名）・氏名・住所、帳簿を始める年、申告の種類（青色・白色の説明つき）、
  消費税の課税区分（免税事業者・本則課税・簡易課税（主な事業区分）・2割特例など、その年に選べるもの）、保存方式を決めます
- 免税事業者でなければ、その年の消費税の設定として保存します（経理方式・登録番号などは、あとで事業者設定の「消費税」で）

## 帳簿の保存方式（電子帳簿保存法モード）
帳簿を作るときに次のどちらかを選びます。**対応 → 通常 には戻せません**（DB のトリガーで拒否）。

通常で作った帳簿は、**翌年への繰越のときだけ**、翌年から「電子帳簿保存法に対応」へ切り替えられます。
- 確認が出るのは、通常モードの帳簿で、翌年以降の仕訳がまだ無いとき（その年の初めから履歴を残せるとき）だけです
- 切り替えると、その時点の帳簿を基準点にして記録の連鎖を始めます。対応を始めた年（`strict_from_year`）と切り替えた日時を残し、切り替えたことを履歴に記録します
- **対応外の年を目立たせます**：サイドバーに「○年は電子帳簿保存法の対応外」、年度の選択に「（電帳法の対応外）」、その年を開いている間は画面上部にお知らせ、決算書の見出しに「電子帳簿保存法の対応外（通常の保存）」。事業者設定の保存方式には「○年まで 通常／○年から 対応」と出します

| | 電子帳簿保存法に対応（優良な電子帳簿） | 通常 |
|---|---|---|
| 仕訳の訂正 | 訂正前・訂正後を履歴に記録（理由も任意で） | 上書き |
| 仕訳の削除 | 「削除済み」の印をつけ、内容を履歴に記録（伝票番号は欠番） | 完全に削除 |
| 勘定科目・補助科目の名前変更 | 表示中の年度から新しい名前。過去の年度は元の名前のまま。履歴に記録 | すべての年度に反映 |
| 勘定科目・補助科目の追加・非表示・削除 | 履歴に記録 | 記録しない |
| 期首残高の変更（繰越処理を含む） | 変更前後の金額を履歴に記録 | 記録しない |
| 年度の締め・締めの解除 | 履歴に記録（解除には理由が必須） | 締め・解除はできるが、記録しない |
| 証憑の訂正 | 訂正前後を履歴に記録（理由は必須） | 訂正前後を履歴に記録（理由は任意） |
| 証憑の削除 | 「無効」の印をつける（ファイルと履歴は残る。理由は必須） | 「無効」の印をつけるか、本当に削除（削除したことと最後の内容を記録） |
| 証憑と仕訳のひも付け・解除 | 履歴に記録 | 履歴に記録 |
| 取引先の追加・変更・非表示・削除 | 履歴に記録 | 記録しない |
| 操作したユーザー | 履歴のすべてに記録 | 仕訳・証憑の登録者・最終更新者のみ |
| 改ざんの検知（記録の連鎖・確認コード） | あり | なし（証憑ファイルのハッシュ確認のみ） |
| 「訂正・削除履歴」画面 | あり | なし |

厳密モードの仕組み
- 仕訳は物理削除しない。登録・訂正・削除のたびに、その時点の仕訳の写し（科目名はその年度の名前）を `entry_history` に積み上げる
- 科目・補助科目の名前は `master_names` に「何年から何という名前か」で持つ
- より新しい年度がある状態で、過去の年度の名前は変えられない
- 科目などの変更は `master_history` に記録
- `entry_history` / `master_history` は SQLite のトリガーで UPDATE / DELETE を禁止。削除済みの仕訳も変更不可
- **限界**：SQLite ファイルを外部ツールで直接編集すること自体は防げない。ソフトとして保証できる範囲と、
  法令上の保存要件との差は、研究上の論点として残している（下の「足りていないところ」参照）
- **消費税**：税区分・インボイス区分も仕訳の一部として、訂正の履歴と照合の対象にしている（「消費税」の節）

## 科目と補助科目
- 勘定科目は区分ごとのコード範囲で追加できます（資産 100〜199、負債 200〜299、資本 300〜399、
  収益 400〜499、売上原価 500〜599、経費 600〜699、専従者給与等 700〜799）→ 1区分あたり最大100科目
- 初期科目は削除・区分変更・コード変更できません（名前は変更可）
- 初期科目はあとから足すことがあります（帳簿を開いたとき、コードも名前も無ければ入る。同じ名前の科目を自分で足していれば足さない）。貸倒引当金（250）・貸倒引当金繰入（750）・貸倒引当金戻入（751）、開業費（160）・未払消費税等（260）・法定福利費（670）・固定資産除却損（671）は、追加の科目に振る小さいコードとぶつからないように離した。
  法定福利費・固定資産除却損・未払消費税等の税区分の初期値は対象外、開業費は課税仕入
- 専従者給与等の科目を足すときは、決算書の欄（繰入額等＝借方／繰戻額等＝貸方）を選びます（あとから変えられない）
- 現金・事業主貸・事業主借・元入金は、仕組み（繰越・家事按分・帳簿入力）で使うため非表示にもできません。名前は変えられます（例：現金 → 現金預金。プログラムは名前ではなくコードで探しています）
- 追加した科目でも、使用済み（仕訳・期首残高・家事按分の設定のどれかで使っている）なら削除できません（非表示にはできます）
- 補助科目は1科目あたり100件まで
- **決算書の欄**：科目ごとに、青色申告決算書（e-Tax 用のデータ）で書く欄を選べます（考え方は `lib/statementLines.ts`）。年ごとに持ち（`account_lines`。表示中の年から、次に変えた年の前まで。行の無い年は `accounts.statement_line`）、前の年の欄はそのまま残ります。初期値は科目名から自動で、名前の同じ欄（普通預金 → その他の預金 などの言い換えを含む）、無ければ科目名で書く追加の欄。売上（収入）金額の科目はまとめて「売上（収入）金額」
  - 追加の欄には上限があります（経費 6・各種引当金等の繰入額と繰戻額 2・資産 7・負債 7。令和7年分の様式。令和8年分の様式で確かめ直す）。追加の欄は金額のある科目だけに割り当てるので、使っていない科目が欄をふさぐことはありません
  - 足りないときは金額の大きい科目から欄に入れ、残りは経費なら雑費、それ以外は「その他」にまとめて、決算書の画面で知らせます

### 電子帳簿保存法
- [ ] 入力期間は「取引日から何日」の一律の日数。「翌月末まで」のような月単位の決め方や、営業日での数え方には対応していない
- [ ] 入力期間を過ぎて登録した仕訳の「理由」を残す仕組みがない（今は事実がわかるだけ）
- [ ] 締め済みの年度でも、勘定科目の追加・非表示・コード変更はできる（科目は年度で区切っていないため）。名前の変更は厳密モードでは年度ごとなので止めている
- [ ] 締め済みの年度でも、証憑の登録・ひも付けはできる（帳簿の数字は変わらないため）。締めとの関係は要検討
- [ ] 締めを戻していた間に何を直したかは、仕訳の履歴と突き合わせて見る必要がある（戻していた期間ごとの一覧はない）
- [ ] 帳簿間の相互関連性（総勘定元帳 ⇔ 補助簿 ⇔ 証憑）を説明できる形での出力
- [ ] スキャナ保存：認定タイムスタンプ（総務大臣が認定した事業者の RFC 3161）を取り込むときに付けて検証する。付けるまでは、スキャナ保存しても紙の原本の保存が要る（B4 では知らせるところまで。B-01）
- [ ] スキャナ保存：PDF・HEIC・TIFF などは画質を自動で確かめられない（自己申告）
- [ ] スキャナ保存：一般書類の「適時入力方式」、過去分の重要書類のスキャナ保存（適用届出）には対応していない
- [ ] 確認コードの控えを促す仕組みが弱い（年の締めのときに画面・決算書に出すだけ）
- [ ] 勘定科目・補助科目・家事按分の設定は「今の中身との照合」の対象外（履歴の連鎖のみ）
- [ ] 証憑のハッシュは「登録時の履歴」と照らし合わせるだけ。履歴ごと書き換えられると見つけられない（ハッシュの連鎖や外部への記録が必要）
- [ ] 帳簿を開くたびの確認は、全件の中身をハッシュにし直す（問い合わせはまとめたが、仕訳が数万件になると計算の時間はかかる）
- [ ] 科目の区分・コードの変更履歴の画面表示（コード変更は記録済み、区分は変更不可）
- [ ] 取引先の登録番号が実在するか（国税庁の公表サイトとの照合）は確認していない

## 仕様として決めていること
やらないと決めたこと、仕組みの上で受け入れている制限。

- **メールからの直接取り込みはしない**：ローカルで完結する方針のため。メールの添付ファイルは保存してから取り込む
- **届出書を e-Tax で作る・送る機能は持たない**：「電子帳簿保存法」の画面の内容をコピーして、e-Tax や書面で出してもらう
- **締めを戻すときに毎回「編集しますか？」と聞く方式は採らない**：反射的に「はい」を押されやすいため。締めを戻すという明示的な操作にする
- **翌年を始めるには繰越が要る**：年度の一覧は、仕訳か期首残高のある年だけ。繰越は前の年を締めずにでき、何度でもやり直せる
- **定型仕訳の登録・変更は履歴に残さない**：帳簿そのものではないため
- **通常モードでは、削除した仕訳の「誰が削除したか」は残らない**：通常モードは物理削除のため（登録者・最終更新者だけ）。残したい場合は厳密モードを使う
- **強制終了・電源が落ちたときは、ログアウトを記録できない**：利用の記録で「ログアウトの記録なし」と表示して、あとからわかるようにしている
- **改ざんは検知までで、防ぐことはできない**：SQLite のファイルを直接書き換えることは止められない。履歴の連鎖・今の中身との照合・トリガーの見張りで「わかる」ようにしている
- **連鎖をまるごと作り直す改ざんは、確認コードを外に控えていないと見抜けない**：控えるかどうかは利用者まかせ（タイムスタンプは有料のため使っていない）
- **ユーザーのパスワード・権限は、帳簿ファイルを直接書き換えれば変えられる**：成りすましを完全には防げない。帳簿ファイルを暗号化すれば、ファイルのパスワードを知らない人は書き換えられない
- **スキャナ保存の見読可能性（4ポイントの文字が読めること）は、画面の拡大表示に任せる**
- **CSV の数式対策はしない**：摘要などは記録したとおりに書き出す（市販の会計ソフトと同じ）。= + - @ で始まる摘要は、Excel で開くと数式として扱われることがある

## 開発方針
- **個人・法人は1つのソフトで扱う**：将来は、帳簿を作るときに「個人／法人」を選ぶ（保存方式と同じく、あとから変更不可）
- **法人対応までに守ること**（あとで大きな作り直しをしないため）
  - 会計期間の開始日・終了日は、必ず `lib/accounting.ts` の `yearStart` / `yearEnd` を通す（日付を直接 `1月1日`・`12月31日` と書かない）
  - 個人特有の処理（元入金の再計算、事業主貸・事業主借の扱い、青色申告特別控除）は1か所にまとめ、「個人の場合の処理」として分けておく
  - 決算書・試算表の見出し（「資本」「元入金」など）は画面に直接書かず、区分の定義（`constants/accounts.ts`）から引く
- **書き込みは1つずつ順番に行う**：すべての書き込みは `repo.ts` の `tx()` の待ち行列に並ぶ。tx の中から別の tx を呼ぶと待ち合わせて止まるので、中では「_」つきの関数を使う
- **画面を変えたら説明書も直す**：画面の名前・ボタン・手順を変えたら、同じ変更で `docs/manual/operation.md`（操作説明書）の節を直す。保存・履歴・検索・出力などの仕組みを変えたら `docs/manual/system.md`（システム概要書）も。左のメニューの画面は、操作説明書の「画面の一覧」にすべて載せる（`lib/markdown.test.ts` で確かめる）
- **トリガーの条件を変えるときは、名前を変えて作り直す**：`CREATE TRIGGER IF NOT EXISTS` なので、同じ名前のままでは既存の帳簿に反映されない。古い名前は `schema.ts` の `RETIRED_TRIGGERS` に入れる（開いたときに消し、消されていたとは数えない）

## データファイル
- `書類/domble/*.dmbl` が帳簿ファイル（1ファイル = 1事業者、複数年を保存）
- 開くとき（開く前の状態）と閉じるときに `書類/domble/Backup/` へ `.dmbk` として自動バックアップ。事業者設定の「今すぐバックアップ」でも作れます。前回、保存の途中でソフトが止まっていても書きかけを含まないよう、開いて SQLite が元に戻したあとに複製します。作れなかったら画面で知らせます
- **2か所目**：事業者設定で、外付けディスクなど2か所目のフォルダを PC ごとに決められます（決めたら、どのバックアップも両方に作る）
- **残し方**：直近の世代数（既定 100）に加えて、日ごとに1つ（30日分）と月ごとに1つ（7年分）を残し、ほかは開いたときに消します。名前は `帳簿名_YYYYMMDD-HHMMSS.dmbk`。戻す前に作る `…_戻す前.dmbk` は消しません
- 閉じるときと今すぐのバックアップは、開いている帳簿を SQLCipher の書き出し（`sqlcipher_export`）で写すので、暗号化した帳簿は暗号化されたままです（保存の途中には書き出さない）
- バックアップ（`.dmbk`）は **読み取り専用** で開きます。ファイルを読み取り専用で開いて中身をメモリに写し、その写しを表示するので、元のファイルには一切書き込みません（古い形式の列の追加も写しにだけ行う）。
  登録・訂正などはすべて止め、年度の切り替えだけできます。開いたときの記録（ログイン・連鎖の開始・締めの初期化・バックアップの整理など）も行いません
- **戻す**：事業者設定のバックアップの一覧から選びます（管理者のみ）。今の帳簿を「戻す前」の印つきでバックアップしてから閉じ、バックアップで置き換えて開き直します。厳密モードでは、戻したこと（どのバックアップから・戻す前の帳簿の場所）を検知の記録に残します
- **使用中の目印**：開いている間、帳簿ファイルの隣に `帳簿名.dmbl.lock`（PC の名前・開いた日時）を置き、閉じたら消します。目印があれば「読み取り専用で開く／それでも開く／やめる」を聞きます（同じ PC の分は、前回正しく閉じられなかったとき）。同期フォルダ（iCloud Drive・Dropbox など）の中の帳簿は、開いたときに2台で同時に開かないよう知らせます
- **形式の版**：帳簿に形式の版（`settings.schema_version`）を持ち、ソフトより新しい版の帳簿は読み取り専用で開きます（古い版で書き込むと、新しい版で入れた項目が消えるため）
- 証憑のファイルも帳簿ファイルの中に入るので、1ファイルを持ち運べばすべてそろう
- 暗号化した帳簿ファイルは、パスワード（または回復キー）がないと開けません（「帳簿ファイルの暗号化」を参照）
