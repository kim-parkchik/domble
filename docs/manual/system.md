# domble システム概要書

この書類は、電子帳簿保存法で備え付けるシステム関係書類のうち「システム概要書」に当たるものです。
domble の仕組み（データの持ち方、訂正・削除の履歴、検索、出力、保存）をまとめています。操作の手順は「操作説明書」を見てください。

## 概要

- **名称**：domble（個人事業主のための会計ソフト）
- **動作環境**：macOS のパソコンで動くアプリです（Windows・Linux は未確認）
- **作り**：画面は React と TypeScript、アプリの土台は Tauri、データは SQLite です
- **ネットワーク**：使いません。インターネットにつなぐのは、事業者設定の「最新の祝日を取得」を押したときだけです（取得先は内閣府に決め打ち）
- **JIIMA 認証**：受けていません。要件を満たしていれば、優遇措置は受けられます

## 帳簿ファイル

- 1つの事業者の帳簿を、1つのファイル（拡張子 .dmbl）に保存します。複数の年を1つのファイルに持ちます
- 証憑（請求書・領収書などのファイル）も帳簿ファイルの中に入るので、1つのファイルですべてそろいます
- 既定の保存場所は、書類フォルダの「domble」です
- 主なデータ

| データ | 中身 |
|---|---|
| 仕訳（journal_entries・journal_lines） | 日付・伝票番号・借方と貸方の科目と金額・摘要・取引先・税区分・登録者と登録日時 |
| 勘定科目（accounts・sub_accounts・master_names） | 科目と補助科目。名前は年度ごとに持つ |
| 期首残高（opening_balances） | 年度ごとの1月1日の残高 |
| 証憑（evidences・evidence_files・evidence_links） | 取引年月日・金額・取引先、受け取ったままのファイルと SHA-256、仕訳とのひも付け |
| 履歴（entry_history・master_history・evidence_history） | 登録・訂正・削除のたびの写し（仕訳・科目などは電子帳簿保存法に対応した帳簿、証憑はどちらの保存方式でも） |
| 削除した証憑の記録（evidence_deletions） | 通常の保存方式で証憑を本当に削除したときの、日時・理由・最後の内容 |
| 記録の連鎖（audit_chain） | 履歴を書くたびのハッシュの連なり |
| 締め（fiscal_closings） | 年度ごとの「何月まで締めたか」と確認コード |
| 固定資産台帳（fixed_assets・asset_rates・asset_amortizations） | 資産ごとの取得日・取得価額・償却方法・耐用年数・売却や除却の日、年ごとの事業専用割合、繰延資産の年ごとの償却額 |
| 棚卸（inventory_counts） | 年ごとの期末の棚卸高と棚卸表（品名・数量・単価） |
| ユーザー（users）と利用の記録（access_log） | 使う人・権限・パスワードのハッシュ、ログイン・ログアウト |

## 保存方式

帳簿を作るときに選びます。電子帳簿保存法に対応した方式から通常には戻せません（データベースのトリガーで拒否します）。
通常で作った帳簿は、翌年への繰越のときだけ、翌年から対応に切り替えられます。切り替えた年より前の年は「対応外」として画面と印刷で目立たせます。

| | 電子帳簿保存法に対応（優良な電子帳簿） | 通常 |
|---|---|---|
| 仕訳の訂正 | 訂正前・訂正後を履歴に記録 | 上書き |
| 仕訳の削除 | 「削除済み」の印をつけ、内容を履歴に記録 | 完全に削除 |
| 科目・期首残高・締めなどの変更 | 履歴に記録 | 記録しない |
| 証憑の訂正・削除 | 訂正前後を記録、削除は「無効」の印 | 訂正前後を記録、削除は「無効」の印か本当に削除（削除したことを記録） |
| 改ざんの検知 | 記録の連鎖・確認コード | 証憑ファイルのハッシュの確認のみ |

## 訂正・削除の履歴

- 仕訳は物理的に削除しません。登録・訂正・削除のたびに、その時点の仕訳の写し（科目名はその年度の名前）を履歴に積み上げます
- 履歴には、操作した日時・操作した人・訂正や削除の理由を残します
- 履歴のデータは、データベースのトリガーで書き換えと削除を禁止しています。削除済みの仕訳も変更できません
- 科目名は「何年から何という名前か」で持つので、名前を変えても過去の年度の帳簿は元の名前のまま出ます

## 改ざんの検知

帳簿ファイルは SQLite のファイルなので、domble を通さずに書き換えること自体は防げません。そこで、書き換えを見つけられるようにしています。

1. **記録の連鎖**：履歴を1件書くたびに、1つ前の記録のハッシュを含めたハッシュを積みます。履歴を書き換え・削除すると、そこから先が合わなくなります
2. **今の中身との照合**：仕訳・証憑・期首残高・締め・固定資産台帳について、最後に記録した状態のハッシュと今の中身を比べます
3. **トリガーの見張り**：履歴を守るトリガーが消されていたら、記録して知らせます
4. **確認コード**：年を締めたときの確認コード（連鎖の先頭のハッシュの一部）を決算書の控えなど帳簿ファイルの外に残しておくと、連鎖をまるごと作り直されても見つけられます

1〜3 は帳簿を開くたびに行います。証憑ファイルの中身を含めた確認は「改ざんの確認」で行います。

## 入力期間の記録

- 仕訳ごとに、最初に登録した日時を残します（電子帳簿保存法に対応した帳簿では、書き換えられない登録時の履歴から取ります）
- 取引日から入力期間（事業者設定。既定 70 日）を過ぎて登録した仕訳を「遅れて登録」として表示し、絞り込めます

## 検索

- 仕訳：取引年月日（期間）・金額（範囲）・科目・取引先・税区分・摘要などを組み合わせて検索します
- 証憑：取引年月日（範囲）・取引金額（範囲）・取引先を組み合わせて検索します

## 出力

- 仕訳日記帳・総勘定元帳（補助元帳）・出納帳・残高試算表・固定資産台帳・訂正削除履歴を、A4 縦で印刷できます。
  各ページに帳簿の名前・屋号と氏名・期間・ページ番号・出力日を入れ、1つの仕訳がページをまたがないように分けます。印刷の画面から PDF にも保存できます
- 同じ帳簿を CSV で書き出せます。証憑は、ファイルを一覧の CSV と一緒に書き出せます

## 帳簿間の関連

- 仕訳帳（仕訳日記帳）・総勘定元帳・出納帳などの補助簿は、同じ仕訳のデータから作るので、伝票番号でつながっています
- 証憑と仕訳は、ひも付けで結びます（1つの仕訳に複数の証憑、1つの証憑に複数の仕訳も可）

## 締め

- 年度ごとに「何月まで締めたか」を持ちます。締めた月までの仕訳と、年を締めた年度の期首残高などへの書き込みは、画面とデータベースのトリガーの両方で拒否します
- 消費税・申告の種類・家事按分・科目名・決算書の欄・不動産所得の規模などは「何年から」で持ちます。締めた年が引き継いでいる設定を変える書き込みも、画面とトリガーの両方で拒否します
- 年を締めた年に使っている固定資産は、売却・除却の日（締めた年の台帳が変わらないもの）と、締めていない年からの事業専用割合のほかは変えられません（追加・削除も）
- 締めと戻しは管理者だけができ、電子帳簿保存法に対応した帳簿では戻す理由が必須で、履歴に残ります

## ユーザーと権限

- 権限は、管理者・入力担当・閲覧のみの3つです。権限は画面だけでなく、書き込みの入り口でも確かめます
- パスワードは任意です（PBKDF2-SHA256 のハッシュで保存）
- ログイン・ログアウトを利用の記録に残します。履歴に名前が残るので、ユーザーは削除できません（非表示にはできます）

## 暗号化（任意）

- 帳簿ファイル全体を SQLCipher の形式で暗号化できます（AES-256。改ざん検知の HMAC つき）。鍵はパスワードから Argon2id で作ります
- パスワードを忘れたときのために回復キーを出します。OS の鍵の保管庫に鍵を預けて、その PC ではパスワードを聞かずに開くこともできます

## 保存とバックアップ

- 書き込みはすべてトランザクションの中で行います。途中で止まっても、SQLite が書きかけを丸ごと取り消します。止まったことは次に開いたときに知らせます
- 新しい版で項目を足したときは、帳簿を開いたときに列を足します。列の追加ではできない変更（選べる値を広げるなど）は、テーブルを作り直して中身を写します（1つのトランザクションで、失敗したら元に戻す）
- 帳簿を開くたびに、書類フォルダの「domble/Backup」へバックアップ（.dmbk）を作ります。決めた世代数（既定 100）を超えたら古いものから消します
- バックアップは読み取り専用で開き、元のファイルには書き込みません
- 保存期間（7年など）の間、帳簿ファイルとバックアップを保管してください

## 証憑の保存

- **電子取引**：受け取ったファイルを変換せずに保存し、登録時に SHA-256 を記録します。ファイルの中身は登録後に差し替えられません。
  登録・訂正・無効・ひも付けは、保存方式にかかわらず証憑ごとの履歴（evidence_history）に残します。通常の保存方式で本当に削除したときは、削除したことと最後の内容を evidence_deletions に残します。
  タイムスタンプは付けないため、真実性の要件は訂正及び削除の防止に関する事務処理規程で満たします（ひな形は電子帳簿保存法の画面）
- **スキャナ保存**：電子帳簿保存法に対応した帳簿だけで使えます。受領日・入力期限（営業日で数える）・画質（200dpi 相当以上、重要書類はカラー）を確かめ、結果を記録します。
  タイムスタンプは付けず、登録日時は PC の時計なので、スキャナ保存の要件は満たしません。読み取った書類も紙の原本を保存します

## この書類の管理

- 操作説明書とシステム概要書は、domble の版と一緒に管理しています（アプリの「操作説明書」の画面で、その版の内容を読む・印刷できます）
- 画面や仕組みを変えたときは、同じ版でこの書類も直します
