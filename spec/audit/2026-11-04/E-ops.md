## 指摘

### E-01 通常モードで、決算整理・台帳から作った仕訳を消せない（FOREIGN KEY constraint failed）
- 判定：誤り
- 重さ：C
- 制度の根拠：該当なし（通常モードは「削除は完全に削除」と説明している：docs/manual/system.md:47、operation.md:23）
- コードの根拠：src/db/repo.ts:2511-2530（通常モードの削除は evidence_links・home_use_runs・depreciation_runs・allowance_runs・sales_docs・sales_payments の参照だけ外し、asset_disposals・year_end_runs・entry_reversals を外さない）、src/db/schema.ts:479-485（asset_disposals.entry_id）・504-510（year_end_runs.entry_id）・519-522（entry_reversals.entry_id・reversal_id）、repo.ts:2871-2874・2968-2973（金額なしの作り直しは deleteEntry_）、features/entry/VoucherForm.tsx:187-205（訂正の画面の削除は、作った仕訳でも押せる）
- 内容（再現：work-E/fk_standard.test.ts・fk_standard2.test.ts。厳密モードはどれもできる）：
  - 通常モードで、固定資産台帳の「売却・除却の仕訳」を仕訳の画面から削除 → 「削除できませんでした：FOREIGN KEY constraint failed」
  - 決算整理の画面の棚卸の振替（未払消費税等も同じ表）を削除 → 同じ。棚卸を直して金額なしで「振替の仕訳を作る」（仕訳を消す道）も同じエラーで、間違って作った振替を消せない
  - 「翌年1月1日付で振り戻す」で作った振り戻しの仕訳、その元の決算整理仕訳を削除 → 同じ。まとめて削除・取り込みの記録の削除に混ざると、全部が失敗
  - 利用者は英語のメッセージしか見えず、何が使っているのか分からない。訂正で金額を変えて逃げるしかない
- 直し方の案：通常モードの deleteEntry_ で、asset_disposals・year_end_runs の行を消し、entry_reversals は entry_id・reversal_id のどちらかが一致する行を消す（前回の E-05 と同じく、journal_entries を参照する表を一覧にして漏れをテストで確かめる：`SELECT m.name FROM sqlite_master m, pragma_foreign_key_list(m.name) f WHERE f."table" = 'journal_entries'` の全部を通常モードの削除で消すかをテストする）。

## 画面の自動テストの案

### 前提
- Tauri の公式の WebDriver（tauri-driver）は、デスクトップでは Windows と Linux だけで、macOS は使えない（「macOS has no WKWebView driver tool available」。Tauri の資料 https://v2.tauri.app/develop/tests/webdriver/ ）。macOS で Tauri の本物のウィンドウを自動で操作するのは、アプリの中に WebDriver を組み込む別の仕組みが要り、手間が大きい
- 本番の画面は macOS の WKWebView（WebKit）。Rust 側（db.rs・files.rs・crypt.rs）は cargo test で、会計の計算と repo は bun test で、すでに確かめている
- .claude/preview に、Tauri の呼び出し（invoke）を `@tauri-apps/api/mocks` の mockIPC で差し替え、DB は bun:sqlite の模擬サーバー（1441）、画面は Vite（1440）で動かす仕組みがある。ポートを変えれば帳簿を data-<PORT>/ に写して使う（run.sh）

### 比べた案
| | A. Playwright ＋ 今の preview | B. bun test ＋ happy-dom ＋ Testing Library | C. Tauri のウィンドウを直接（WebdriverIO の組み込み） |
|---|---|---|---|
| 入れるもの | `@playwright/test`（開発用の依存）と、ブラウザ 1 つ（WebKit なら おおよそ 100MB 前後、Chromium は 150MB 前後。~/Library/Caches/ms-playwright に入る） | `@happy-dom/global-registrator`・`@testing-library/react`・`@testing-library/user-event`（合わせて数 MB、ブラウザ不要） | WebdriverIO 一式とアプリ側のプラグイン（Rust の依存も増える） |
| 速さ | 起動（Vite ＋ 模擬 DB）数秒、1 本 数秒。最初の 10 本で 30 秒〜1 分 | 1 本 数十〜数百 ms。bun test にそのまま並ぶ | アプリのビルドが要り、1 回 数分 |
| 確かめられること | 画面をまたぐ流れ（メニュー → 入力 → 登録 → 帳簿・履歴に出る）、印刷用の表示、キーボード（Enter で次の欄）、読み取り専用・権限のボタン、本物に近い WebKit の動き | 部品ごとの入力と確かめ（DateInput・VoucherForm の止め方、ボタンの有効・無効）。DB は makeDb の bun:sqlite をそのまま渡せる | 本物（Rust の DB・ファイル・暗号化・ダイアログ）まで |
| 本物との違い | Rust 側は模擬（server.ts）。暗号化・ファイルのダイアログ・ロックはまね。WebKit は Safari に近いが WKWebView と全く同じではない | レイアウト・CSS・印刷・フォーカスの動きが本物と違う。Tauri のダイアログ（ask など）は差し替えが要る。日本語変換（IME）は扱えない | 違いは最も少ない |
| 保守の手間 | 模擬（server.ts）を Rust のコマンドと合わせ続ける（今もしている）。画面の文言・role で探すので、文言を変えるとテストも直す | 画面の部品が AppContext に強く頼るので、テスト用の Provider を作る。部品の作りを変えるとテストも直す | 大きい（macOS 用の仕組みが新しく、資料も少ない） |
| CI が無い今の運用 | 手元で `bun run test:e2e` を、コミットの前・版を出す前に回す。ブラウザの取得は最初の1回（インターネットが要る） | `bun test` に入るので、今の習慣のまま毎回回る | 向かない |

### 推奨：A（Playwright の WebKit だけ ＋ 今の preview の仕組み）を主に、必要なら B を少し
- 理由：守りたいのは「画面の操作の組み合わせでデータを壊さない・法令の表示を崩さない」ことで、これは画面をまたぐ流れでしか確かめられない。preview の模擬はすでにあり、Tauri の公式の自動操作は macOS で使えない。本番が WebKit なので、ブラウザは WebKit だけ入れる（Chromium・Firefox は入れない）
- 入れるとき：`.claude/preview` のうち mock.ts・server.ts・vite.config.ts を git に入る場所（例：`e2e/harness/`）に移す（帳簿の .dmbl は .gitignore のまま）。テスト用の帳簿は手作りの preview.dmbl を使わず、テストの初めに repo の関数（makeDb と同じ作り方）で作ってファイルに書く（毎回同じ状態から始められ、形式の版が上がっても作り直せる）。ポートは 1450 などテスト専用にして、ほかの確認用サーバーとぶつけない
- B は、DateInput・VoucherForm のように入力の確かめが細かい部品だけに足す（ブラウザ不要で速い）
- インストールはしていない（この確認では何も入れていない）

### 最初に書くテストの候補（データを壊しやすい・法令に関わる流れ）
1. 振替伝票：正しくない日付（4/31・前の年）・貸借の不一致では登録されず、正しく直すと登録され、仕訳日記帳に出る。厳密モードで訂正すると訂正・削除履歴に訂正前・訂正後が出る
2. 締め：月の締めをすると、その月の仕訳の訂正・削除のボタンが押せず、締めを戻す（理由が必須）と押せる。年の締めのあと、勘定科目・期首残高・固定資産台帳が読むだけになる
3. 通常モードで、決算整理の画面の棚卸の振替・固定資産の売却除却・振り戻しの仕訳を作ってから仕訳の画面で削除する（E-01 の再発を防ぐ）
4. 請求書：下書き → 発行（売掛金の仕訳ができる）→ 直す（同じ仕訳が訂正）→ 入金 → 取消は入金を消すまでできない。適格請求書の記載事項（登録番号・税率ごとの対価と消費税額・※）が印刷用の表示に出る。免税の年は出ない
5. 読み取り専用（バックアップ .dmbk を開く・使用中の帳簿を読み取り専用で開く）：どの画面でも保存・削除のボタンが押せないか、押しても帳簿が変わらない（E-04）
6. バックアップ：今すぐバックアップ → 仕訳を足す → 戻す → 足した仕訳が無く、「戻す前」のバックアップが一覧に残り、厳密モードでは戻した記録が出る
7. 明細の取り込み：同じ CSV を2回読んでも二重にならない、取り込みの記録からまとめて削除すると明細が未登録に戻る
8. 権限：入力担当で事業者設定・締め・消費税の保存ができない（案内が出る）、閲覧のみで何も変えられない

いちばん大事な3点
1. **通常モードで、決算整理・台帳から作った仕訳を消せない（E-01、再現済み）**：売却・除却、棚卸の振替・未払消費税等、振り戻しの仕訳を削除すると「FOREIGN KEY constraint failed」。決算整理の画面で金額なしにして作り直すのも同じで、間違って作った振替を消せない。通常モードの削除で asset_disposals・year_end_runs・entry_reversals の参照を外し、journal_entries を参照する表すべてをテストで確かめる
2. **厳密モードの「戻す」で履歴が帳簿から消える（E-02）**：戻した時点より後の訂正・削除の履歴が帳簿ファイルから無くなり、残るのは「戻した」の1行だけ。確認の文に書き、理由を必須にし、記録を「戻す前」のバックアップ側にも残す
3. **画面の自動テストを入れる（E-12）**：Playwright（WebKit だけ）で今の preview の模擬を動かすのが、macOS の Tauri に合う。最初は日付・締め・通常モードの削除・請求書・読み取り専用・戻すの流れから
